Статус: утверждена (просьба директора 2026-11-20, по снимкам экрана «Камеры»)
PRD: docs/PRD.md → экран «Камеры»

## Зачем — главная сессия

Инженер QA ставит камеры на стенд через окно «Камера на место», где пароль скрыт звёздочками, а логин, порты и пароль приходится вводить для каждой камеры заново в отдельном окне. Директор 20.11: для инженера QA пароль камеры не секрет, его надо видеть; логин, пароль и прочие данные для входа удобнее задавать прямо в таблице найденных камер.

## Поведение (BDD) — главная сессия

### S1: пароль виден открытым текстом

- **Дано** окно «Камера на место стенда»
- **Когда** инженер вводит пароль
- **Тогда** пароль виден буквами, а не звёздочками

### S2: данные для входа задаются в таблице

- **Дано** поиск нашёл камеру
- **Когда** инженер правит в её строке HTTP- и RTSP-порт, адрес за туннелем, логин, пароль, производителя и выбирает место в колонке «Место»
- **Тогда** камера встаёт на это место с этими данными, без отдельного окна; пароль — в хранилище паролей, не в файле стенда

### S3: правка камеры, уже стоящей на месте

- **Дано** камера на месте (найдена поиском или добавлена вручную) — её строка в таблице показывает место, логин и пароль
- **Когда** инженер меняет в строке логин, пароль, порт, адрес за туннелем или производителя
- **Тогда** камера на месте сразу работает с новыми данными: файл стенда и хранилище паролей обновлены

### S4: смена места и снятие

- **Дано** камера на месте 1
- **Когда** инженер выбирает в колонке «Место» другое свободное место или «—»
- **Тогда** камера переезжает на новое место или снимается с места; плитки мест показывают то же

### S5: ошибка ввода

- **Дано** строка таблицы
- **Когда** в порт вписано не число 1–65535 или адрес за туннелем с «/», «@», пробелом
- **Тогда** программа говорит, что не так, и оставляет прежнее значение

### S6: повторный поиск не теряет правки

- **Дано** в строке найденной камеры вписаны логин и пароль, камера не на месте
- **Когда** инженер снова нажимает «Найти камеры»
- **Тогда** вписанное в строке остаётся

### S7: производитель «Рувер» узнаётся по паспорту ONVIF

- **Дано** камера в поиске называет себя «Ruware-Hisi»
- **Тогда** в колонке «Производитель» стоит «ruver», а не «generic»

### S8: название камеры рядом с адресом (директор 20.11, экраны «Камеры» и «Прогон»)

- **Дано** камера на месте
- **Тогда** плитка места, строка списка прогона и шапка карточки показывают название камеры и адрес: до паспорта прогона — паспорт ONVIF из поиска, без него — производитель из таблицы («Рувер», «Dahua»); после паспорта прогона — его производитель и модель; если не известно ничего — «марка не указана» на плитке и один адрес в прогоне
- **И** разметка в названии из ответа камеры показывается текстом

### S9: протокол в Markdown (директор 20.11, экран «Протоколы»)

- **Дано** прогон завершён
- **Тогда** рядом с PDF, Excel и HTML выпущены `protocol_<место>.md` и `summary.md`, а на экране «Протоколы» есть кнопка «Открыть Markdown»
- **И** у прогона прошлой версии без .md файл собирается из базы прогона при первом открытии
- **И** для сравнений и карты API кнопка объясняет, что Markdown есть только у протоколов и сводки
- **И** ответы камер в .md экранированы, пароли вырезаны, как в HTML

## Вне рамок — главная сессия

- В самой камере логин, пароль и сеть не меняются (табу, never.md): правится только то, с чем программа входит в камеру.
- Пароли по-прежнему хранятся только в системном хранилище: не в stand.yaml, не в базе, не в протоколе.
- Окно «Добавить вручную…» остаётся для камер, которых нет в поиске.

## UI — ui-designer

Таблица «Найдено камер» — колонки: Место (выпадающий список «—» и свободные места), Адрес, HTTP-порт, RTSP-порт, Логин, Пароль, Производитель (выпадающий список адаптеров), Паспорт ONVIF (производитель и модель из поиска, только чтение), Адрес за туннелем. Строки — найденные поиском камеры и камеры на местах, которых поиск не нашёл. Кнопка «Поставить на место» ставит выбранную строку на первое свободное место без окна.

## Архитектура, API и данные — backend-architect

Только `gui/screens/cameras.py` и `gui/camera_dialog.py`. Строка таблицы — черновик камеры в памяти экрана; на стенд она уходит через существующие `Stand.add_camera` / `remove_camera` и `secrets.set_password`. Модель `Camera` и формат stand.yaml не меняются.

## Безопасность — backend-architect

Пароль на экране показан открыто (решение директора 20.11: инженеру QA он не секрет). Хранение не меняется: системное хранилище, в stand.yaml, базу и протоколы пароль не попадает (S2 проверяет файл стенда). К камере экран не обращается — табу не затронуто.

## Решения — главная сессия

| Вопрос | Выбрано | Почему | Отвергнуто |
|---|---|---|---|
| Как ставить на место из таблицы | выпадающий список «Место» в строке | одно действие, видно место каждой камеры | окно с повтором данных строки — то, от чего директор просил уйти |
| Камеры, добавленные вручную | тоже строкой в таблице | их логин и пароль иначе не поправить | отдельный экран правки |
| Где хранить название камеры | поле `Camera.name` (уже есть в stand.yaml) — паспорт ONVIF из поиска | плитка и прогон до паспорта видят то же, что инженер видел в поиске | новое поле стенда |
| Приложения в Markdown | только строка «есть в HTML, PDF, Excel» и тревога «не вернулись» под заключением | снимки и графики в тексте не читаются; тревога важнее всего | полный перенос приложений |
| Версия | 0.6.4 | новый формат протокола | — |
| «Ruware-Hisi» → generic | распознавать «ruware», «рувер» как «ruver» | на снимке директора камера «Рувер» стала generic и лишилась проверок своего API | — |
