## Зачем — главная сессия

Нужен работающий «скелет» всей программы: камеры находятся и расставляются по местам 1–8, прогон идёт параллельно с соблюдением фаз и блокировок стенда, по каждой камере выходит протокол (PDF, Excel, HTML) с таблицей задач. Окно с подсказками и F1, сборки для Windows и Linux. Проверок пока одна — «связь и паспорт камеры»; модули этапов 2–10 встраиваются в готовый каркас без его переделки.

## Поведение (BDD) — главная сессия

### S1: Поиск камер в сети
- **Дано** в подсети стенда включены камеры с ONVIF
- **Когда** инженер нажимает «Найти камеры»
- **Тогда** за ≤ 10 с появляется список: IP, производитель, модель, есть ли уже на стенде

### S2: Добавление камеры вручную и хранение пароля
- **Дано** камера не отвечает на поиск (другая подсеть, выключен WS-Discovery)
- **Когда** инженер вводит IP, логин и пароль
- **Тогда** камера добавляется; пароль лежит в системном хранилище паролей, в `stand.yaml` и в базе его нет

### S3: Расстановка по местам и месту стенда
- **Дано** найдено 9 камер
- **Когда** инженер ставит их на места 1–8 и выбирает место стенда «цветовой бокс» или «тёмная комната»
- **Тогда** 8 камер на местах; девятую поставить нельзя — подсказка «свободных мест нет»

### S4: Параллельный прогон 8 камер
- **Дано** на стенде 8 камер, выбран сценарий
- **Когда** инженер нажимает «Начать прогон»
- **Тогда** все 8 проверяются одновременно; на экране «Прогон» по каждой — текущая проверка, счётчики прошло/не прошло, общий прогресс; по окончании — протокол по каждой камере и сводный отчёт
- **Когда** инженер нажимает «Остановить» посреди прогона
- **Тогда** начатые проверки дорабатывают или прерываются по тайм-ауту, неначатые — «пропущена: прогон остановлен»; протоколы и сводный отчёт выпускаются по сделанному

### S5: Камера пропала посреди прогона
- **Дано** прогон идёт
- **Когда** у камеры 3 пропадает сеть
- **Тогда** проверка, во время которой камера перестала отвечать, — «не прошла» с задачей программистам (сбой камеры или прошивки, решение директора 2026-11-03); остальные её проверки — «ошибка стенда: нет связи»; если камера пропала между проверками — все оставшиеся «ошибка стенда: нет связи»; остальные 7 камер доходят до конца; протокол камеры 3 всё равно выпускается. Неверный логин или пароль камеры — «ошибка стенда» (настройка стенда и подключения), не задача

### S6: Фазы и общее оборудование
- **Дано** в сценарии есть проверки сетевой, синхронной, поочерёдной и стресс-фаз
- **Когда** идёт прогон
- **Тогда** фазы идут по порядку; проверки, которым нужен один ресурс стенда (свет, экран, динамик, микрофон), не идут одновременно; синхронная проверка стартует на всех камерах разом, после готовности всех

### S7: Протокол камеры
- **Дано** прогон закончен
- **Когда** инженер открывает протокол камеры
- **Тогда** в нём: номер протокола, дата, стенд и место, модель, серийный номер, прошивка (из камеры); сводка по модулям; по каждой проверке — что делали, ожидание, факт, результат, порог и откуда он взят, доказательство; таблица задач программистам — строка на каждую «не прошла»; «ошибка стенда» и «пропущена» в задачи не попадают

### S8: Excel и сводный отчёт
- **Дано** прогон закончен
- **Когда** инженер выгружает Excel
- **Тогда** в книге листы «Сводка», «Проверки», «Задачи» по каждой камере и лист «Сравнение» — матрица «проверка × камера»

### S9: Подсказка через 1 секунду
- **Дано** открыт любой экран
- **Когда** мышь держится на элементе 1 секунду
- **Тогда** показывается подсказка «что это и что делать»; у каждого видимого элемента управления она есть (иначе автотест сборки падает)

### S10: Справка по F1
- **Дано** открыт экран или элемент в фокусе
- **Когда** нажата F1
- **Тогда** открывается справка на разделе этого экрана или элемента; работает без интернета

### S11: Прогон без окна
- **Дано** готовый `stand.yaml`
- **Когда** запускается `qa-tool run --stand stand.yaml`
- **Тогда** получаются те же протоколы, что из окна; код выхода 0 — всё прошло, 1 — есть «не прошла», 2 — ошибка стенда или конфигурации

### S12: Установка на Windows и Linux
- **Дано** установщик из CI (Windows — `.exe`, Linux — AppImage)
- **Когда** его ставят на чистую машину
- **Тогда** программа запускается, ffmpeg внутри, справка открывается

### S13: Секреты не попадают в протокол
- **Дано** проверка сохранила обмен с камерой как доказательство
- **Когда** формируется протокол
- **Тогда** пароли, заголовки Authorization, WS-Security UsernameToken и cookie сессии заменены на `***`

### S14: Разрушающие проверки выключены по умолчанию
- **Дано** в сценарии есть проверка с пометкой «разрушающая»
- **Когда** прогон запущен без галочки «разрешить разрушающие»
- **Тогда** проверка «пропущена: не разрешено сценарием», камера не трогается

## Вне рамок — главная сессия

- Проверки модулей этапов 2–10 (кроме «связь и паспорт камеры»).
- Драйверы оборудования стенда (реле, звук, свет) — этап 6; в каркасе только ресурсы-блокировки и их mock.
- Пакет `.deb` — этап 9; сейчас AppImage.
- Подпись установщиков сертификатом.

## UI — ui-designer

Окно: слева меню из пяти экранов, сверху — статус стенда (место, камер на местах, идёт ли прогон).

| Экран | Что на нём | Состояния |
|---|---|---|
| Стенд | место стенда (бокс / тёмная комната), папка прогонов, ресурсы стенда и их состояние (в каркасе — «не подключено») | пусто, ок, ошибка |
| Камеры | кнопка «Найти камеры», «Добавить вручную»; таблица найденных; 8 плиток мест с камерой, производителем, моделью | поиск идёт, ничего не найдено, нет связи, нет мест |
| Сценарий | дерево модулей и проверок с галочками (недоступные для производителя — серые с объяснением), галочки «разрешить изменяющие» и «разрешить разрушающие», длительность стресса | — |
| Прогон | 8 плиток: камера, текущая проверка, прошло/не прошло/пропущено, полоса прогресса; кнопки «Начать», «Остановить» | ожидание, идёт, остановлен, завершён |
| Протоколы | список прогонов (дата, камеры, итог); открыть PDF / Excel / HTML камеры или сводку | пусто, список |

- Подсказки: у каждого элемента `toolTip` и свойство `help_id`; задержка показа 1000 мс.
- F1: окно справки (Markdown из `docs/manual/`), раздел по `help_id` элемента в фокусе или под мышью, иначе — по экрану.
- Тексты по-русски, шрифт системный, тёмная и светлая тема — системные.

## Архитектура, API и данные — backend-architect

**Компоненты (сценарии):**
- `core/models.py` — Camera, Slot, Stand, Scenario, CheckSpec, CheckResult, Run (все S).
- `core/checks.py` — реестр проверок: декоратор `@check(id, module, title, phase, resources, vendors, writes, destructive)`; функция `(ctx) -> CheckResult` (S6, S14).
- `core/scheduler.py` — координатор: по одному процессу на камеру (`multiprocessing`, spawn — одинаково на Windows и Linux), фазы по порядку, барьер для синхронной фазы, блокировки ресурсов у координатора, тайм-ауты и «нет связи» (S4–S6).
- `core/store.py` — SQLite прогона, пишет только координатор (S4, S7).
- `core/secrets.py` — `keyring` + вырезание секретов из доказательств (S2, S13).
- `drivers/camera/onvif_generic.py` — подключение, `GetDeviceInformation`, `GetCapabilities`; `drivers/camera/discovery.py` — WS-Discovery (S1).
- `checks/core/connect.py` — проверка `CORE-CONNECT-1`: TCP 80/554, ONVIF отвечает, паспорт камеры в шапку протокола (S7).
- `report/` — один HTML-шаблон (Jinja2) → HTML и PDF (Qt `QTextDocument` + `QPdfWriter`), Excel (openpyxl) (S7, S8).
- `gui/` — окно, пять экранов, стиль с задержкой подсказки, окно справки (S9, S10).
- `cli.py` — `qa-tool` (окно), `qa-tool run`, `qa-tool discover`, `qa-tool --version` (S11).
- `tests/mock_camera.py` — минимальная ONVIF-камера на Python (HTTP + SOAP: GetDeviceInformation, GetCapabilities, WS-Discovery), запускается N экземпляров на разных портах (S1, S4, S5, S11).

**Данные:**
- `stand.yaml` — место, папка прогонов, места 1–8: адрес, порт, логин, производитель; пароли — только в хранилище по ключу `qa-tool/<адрес>`. Для CI — переменная окружения `QA_TOOL_PASSWORD_<n>`.
- `scenario.yaml` — сценарий: модули и проверки, галочки «разрешить изменяющие» / «разрешить разрушающие», длительность стресса; окно сохраняет его рядом со `stand.yaml`, CLI берёт `--scenario` (по умолчанию — все доступные проверки без изменяющих и разрушающих).
- `thresholds.yaml` — пороги: значение, единица, источник («стартовое» / «калибровка <дата>»).
- Прогон: `<папка прогонов>/<номер>/run.sqlite`, `evidence/<место>/<проверка>/…`, `protocol_<место>.{pdf,xlsx,html}`, `summary.{pdf,xlsx,html}`.
- Номер протокола: `QA-ГГГГММДД-ННН`, протокол камеры — `QA-ГГГГММДД-ННН-<место>`.
- Таблица SQLite: `runs`, `cameras`, `results(run, slot, check_id, status, reason, expected, actual, threshold, evidence_path, started, duration)`.

**Сторонние зависимости:** PySide6, onvif-zeep (через onvif-tt на этапе 2), WSDiscovery, keyring, Jinja2, openpyxl, PyYAML; ffmpeg кладётся в сборку: сборки BtbN FFmpeg-Builds, вариант LGPL, закреплённый выпуск — для Windows и Linux. Сборка: PyInstaller (onedir) → Inno Setup (Windows), appimagetool (Linux). CI: GitHub Actions, матрица `ubuntu-24.04` + `windows-latest`.

## Безопасность — backend-architect

- Секреты: пароли камер — только `keyring`; в CI — переменные окружения; в логах, базе, протоколах — `***` (S13).
- Ответы камер — недоверенные данные: экранирование в HTML-протоколе (автоэкранирование Jinja2), очистка имён файлов доказательств.
- Сеть: программа ходит только на адреса со стенда; поиск — WS-Discovery в своей подсети.
- MITRE ATLAS — не применим (нет ML/LLM).

## Решения — главная сессия

| Вопрос | Выбрано | Почему | Отвергнуто |
|---|---|---|---|
| Параллелизм | процесс на камеру + координатор | зависание одной камеры не трогает остальные; spawn одинаков на обеих ОС | потоки (GIL, общий сбой) |
| Mock-камера в каркасе | своя на Python | ставится `pip`, работает на Windows и Linux в CI | mock oxvif (Rust, нужен cargo) — рассмотрим на этапе 2 |
| PDF | Qt `QPdfWriter` из того же HTML | без лишних зависимостей, одинаково на обеих ОС | WeasyPrint (тяжело ставится на Windows) |
| Хранение прогона | SQLite в папке прогона | прогон переносится одной папкой | общая база (сложнее делиться) |
| Linux-пакет | AppImage | один файл, без root | .deb — этап 9 |
| Окружение | uv + Python 3.12 | быстрая воспроизводимая установка на обеих ОС | pip + venv |
