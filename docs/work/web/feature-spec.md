# Спецификация: web

Статус: черновик
PRD: docs/PRD.md → требование 3 (веб-интерфейс любой камеры)

## Зачем — главная сессия

Сейчас веб-интерфейс камер проверяют вручную и выборочно. Директору нужно видеть по каждой камере любого производителя: все ли страницы открываются, какие кнопки и поля работают, сохраняется ли настройка на самом деле, как быстро отвечает интерфейс. Обычный прогон камеру не меняет. Настоящая запись идёт только с галочкой «изменяющие» и всегда с возвратом значения.

## Поведение (BDD) — главная сессия

Три режима защиты действуют всегда, поверх любых галочек: табу AD-7 (S9), опасные кнопки (S10), один вход (S4).

### S1: обход всех страниц

- **Дано** камера с веб-интерфейсом, вход выполнен
- **Когда** идёт сетевая фаза
- **Тогда** программа сама находит страницы (меню, ссылки, вкладки) и открывает каждую; в протоколе строка на страницу: название, адрес, время загрузки, ошибки. Без ошибок и в пределах порога → «прошла»

### S2: ошибка на странице

- **Дано** страница падает с ошибкой в скрипте, пишет ошибку в консоль или получает от камеры ответ 4xx/5xx
- **Когда** программа её открывает
- **Тогда** строка «не прошла», снимок и текст ошибки в доказательствах, задача программистам в протоколе. Ошибки от запросов, которые остановила сама программа (S7), не считаются

### S3: медленный отклик

- **Дано** страница или ответ на нажатие дольше порога (`web.page_load_s`, `web.click_response_s` в конфигурации)
- **Когда** идёт замер
- **Тогда** строка «не прошла» с измеренным временем и порогом

### S4: вход в интерфейс

- **Дано** камера спрашивает логин и пароль формой или окном браузера (Basic, Digest)
- **Когда** программа начинает обход
- **Тогда** она делает ровно одну попытку входа. Исключение из запрета на слова «логин» и «пароль» действует только на запросы от нажатия программой кнопки входа, только до начала обхода, только на странице с одним полем пароля. После входа табу работает полностью

### S5: пароль отвергнут или заблокирован

- **Дано** камера отказала во входе либо пароль уже отвергнут другой проверкой этого прогона
- **Когда** программа пытается войти
- **Тогда** второй попытки нет, «ошибка стенда» с причиной; обход не начинается, задача программистам не создаётся. Отказ в вебе запоминается для всех проверок камеры: поздние проверки потока этот пароль тоже не пробуют

### S6: камера просит сменить пароль

- **Дано** после входа или вместо него показана смена пароля, активация или первая настройка (несколько полей пароля)
- **Когда** программа это видит
- **Тогда** ничего не вводит и не нажимает, «ошибка стенда» с причиной и снимком, обход не идёт

### S7: нажатие без галочки

- **Дано** галочка «изменяющие» выключена
- **Когда** программа меняет поле только в браузере и нажимает кнопку или нажимает кнопку действия
- **Тогда** каждый изменяющий запрос останавливается до камеры; в протоколе: элемент, запрос (метод, адрес), время отклика, пометка «до камеры не дошло, эффект не проверялся». Кнопка дала запрос или изменила страницу → «прошла»

### S8: кнопка не реагирует

- **Дано** доступный элемент не дал ни запроса, ни изменения на странице
- **Когда** программа его нажала
- **Тогда** строка «не прошла», важность мелкая. Недоступный (серый) элемент не нажимается: «пропущена» с причиной

### S9: табу

- **Дано** страница, кнопка или запрос относятся к сети, учётным записям, паролям, безопасности, сбросу, импорту настроек, обновлению
- **Когда** программа до них доходит
- **Тогда** страница только открывается на чтение, ни один элемент на ней не нажимается: «пропущена» с причиной. Запрос, который всё же пошёл, не отправляется (`check_web_request`), на этой строке «ошибка стенда», обход продолжается. Галочки этого не снимают

### S10: опасные кнопки

- **Дано** подпись или запрос говорят о перезагрузке, выключении, форматировании, удалении, очистке
- **Когда** программа до них доходит
- **Тогда** элемент не нажимается ни при каких галочках, в протоколе «есть, не нажат». Такой запрос не уходит, даже если программа ошиблась с подписью

### S11: живые каналы

- **Дано** страница общается с камерой через WebSocket
- **Когда** она отправляет сообщение
- **Тогда** оно проходит те же запреты, что и обычный запрос (S7, S9, S10); видео и события читаются свободно

### S12: настоящая запись с галочкой

- **Дано** галочка «изменяющие» включена
- **Когда** программа меняет поле на другое допустимое значение и нажимает «Сохранить»
- **Тогда** запрос уходит на камеру, страница перезагружается и показывает новое значение; у камеры с адаптером значение дополнительно читается через API. Затем прежнее значение возвращается тем же путём и сверяется. Всё совпало → «прошла»; не сохранилось → «не прошла» с заявленным и прочитанным значением

### S13: настройка требует перезагрузки

- **Дано** камера после записи просит перезагрузку
- **Когда** программа это видит
- **Тогда** камера не перезагружается, значение возвращается, строка «пропущена»: эффект нельзя проверить без перезагрузки

### S14: значение не вернулось

- **Дано** после записи прежнее значение вернуть не удалось
- **Когда** сверка показала расхождение
- **Тогда** важность «блокер», запись на этой камере прекращается до конца прогона, в протоколе: какая настройка, какое было значение, какое осталось. В окне «Прогон» строка появляется по окончании проверки; если процесс камеры снят — из журнала записи

### S15: камера перестала отвечать

- **Дано** камера замолчала во время обхода
- **Когда** прошёл тайм-аут
- **Тогда** «не прошла»; если шла запись — одна попытка вернуть значение после появления камеры, иначе S14

### S16: нужен плагин

- **Дано** интерфейс требует плагин браузера, которого нет
- **Когда** программа открывает такую страницу
- **Тогда** «пропущена» с причиной, а не «не прошла»

### S17: нет веб-интерфейса

- **Дано** порты 80 и 443 закрыты; либо самоподписанный сертификат
- **Когда** программа начинает обход
- **Тогда** порты закрыты → «пропущена» с причиной; сертификат принимается, в протоколе пометка

### S18: лимит сессий

- **Дано** камера отвечает, что подключений слишком много
- **Когда** программа входит
- **Тогда** «ошибка стенда» с причиной, без повторов; обход не идёт

### S19: большие интерфейсы

- **Дано** длинные таблицы, повторяющиеся строки, бесконечные списки, циклы ссылок
- **Когда** идёт обход
- **Тогда** одинаковые элементы проверяются выборочно (`web.same_elements_limit`), обход ограничен `web.pages_limit`, `web.elements_limit`, `web.walk_limit_min`; при срабатывании лимита в протоколе сказано, что осталось не проверенным

### S20: «Стоп» и закрытие

- **Дано** идёт обход
- **Когда** нажат «Стоп» или истекло время проверки
- **Тогда** идущая запись сначала возвращается (не дольше `web.restore_timeout_s`), затем за 5 с браузер закрыт и вход завершён. Временные файлы браузера удалены

### S21: восемь камер сразу

- **Дано** в прогоне 8 камер
- **Когда** идёт сетевая фаза
- **Тогда** у каждой свой браузер без общих данных; падение браузера одной камеры даёт «ошибка стенда» только у неё

### S22: секреты

- **Дано** обход собирает доказательства
- **Когда** они попадают в протокол
- **Тогда** пароли, токены и куки вырезаны из запросов, адресов и текста консоли; снимка экрана с заполненным полем пароля нет; ответы камеры экранируются

### S23: установка

- **Дано** программа установлена на компьютере без интернета (Windows или Linux)
- **Когда** запускается обход
- **Тогда** браузер уже в установщике и работает; не запустился → «ошибка стенда», а не «не прошла»

### S24: сводка

- **Дано** обход закончен
- **Когда** формируется протокол
- **Тогда** сводка: страниц найдено и открыто, элементов нажато, не нажато по запрету и опасных, записей сделано и возвращено; задача программистам — одна на страницу или элемент, без дублей

## Вне рамок — главная сессия

- Сверка веб-значений с ONVIF у чужих камер: значение подтверждается перечитыванием страницы, у адаптера — через API. Влияние на картинку — этап 7.
- Перезагрузка, форматирование, удаление, обновление, сброс через веб — никогда. Форматирование SD — только проверками SD по галочке «разрушающие».
- Адаптеры веб-обхода других производителей: сначала универсальный обход.
- Проверка «Рувер» по карте `routes.ts`: обход универсальный, карта — только для сверки полноты на стенде.

## UI — ui-designer

Новых экранов нет. Модуль появляется в сценарии и на экране «Прогон» обычным порядком, галочка «изменяющие» уже есть (проверяется на Этапе 2 по подсказкам и F1).

## Архитектура, API и данные — backend-architect

**Перехват.** Варианты: A — `context.route` и `context.route_web_socket` в одном модуле, запись отправляется через `route.fetch`; B — Chromium через свой посредник на 127.0.0.1 с разрывом TLS и разбором WebSocket; C — свой CDP `Fetch` на стадии ответа. Выбран A. B видит каждое перенаправление, но это свой прокси с TLS и WebSocket; C спорит с `Fetch` самого Playwright и не покрывает первый запрос всплывающего окна. Цена A: чтение, перенаправленное внутри камеры, видно только после факта (см. «Безопасность»).

|---|---|---|

| `drivers/camera/browser.py` | единственный импорт `playwright`: запуск, контекст, перехват, окна, диалоги, снимки | S4, S7, S9–S11, S17, S20–S23 |

**`browser.py` наружу отдаёт только `BrowserSession`.** Объекты `page`, `context` и `request` не выдаются: `context.request` идёт мимо `route`. Методы: `open(url) -> PageLoad`, `elements() -> list[ElementInfo]`, `click(el) -> Reaction`, `set_field(el, value)`, `read_field(el) -> str`, `screenshot() -> bytes | None`, `login_window()`, `write_window(el)`, `logout_window()`, `close()`. Ошибки: `BrowserMissing` (S23), `BrowserCrashed` (S21), `CameraSilent` (S15), `Stopped` (S20). Один вызов Playwright блокирует не дольше 1 с: ожидание идёт мелкими шагами с опросом `ctx.stop_requested`, паузы только через `wait_for_timeout`, иначе обработчики перехвата не выполняются.

**Решение по запросу:** первое сработавшее правило, в этом порядке, в любом режиме.
1. Схема, адрес или порт не камеры → `STOP_FOREIGN`. Порты: выбранный веб-порт, `camera.port`, 80, 443.
2. GET или HEAD статики без параметров (`is_static_asset`: `.js`, `.css`, `.html`, картинки, шрифты) → пропуск: иначе `/js/edit.js` и `/js/reboot.js` остановили бы страницу.
3. Изменяющий метод с нечитаемым телом → `STOP_WRITE`.
4. `check_http`, `check_onvif` (как `http.py:75-76`) → `STOP_TABOO`, в окнах тоже.
5. `check_web_danger` → `STOP_DANGER`, в окнах тоже.
6. Открыто окно входа или выхода → `check_login_window` / `check_logout_window`; проверка `check_web_request` пропускается.
7. `check_web_request(method, url, body, контекст страницы)`, SOAP как в `http.py:77-79` → `STOP_TABOO`.
8. Открыто окно записи → пропуск.
9. `is_write_request` → `STOP_WRITE`. При нажатии элемента, кроме пунктов меню, ещё `is_web_action` и GET, которого не было при спокойной загрузке страницы (S7).

Остановленный запрос получает `route.abort("blockedbyclient")` и попадает в `StoppedRequest(элемент, метод, адрес, вердикт, мс)`. `STOP_TABOO` и `STOP_FOREIGN` дают «ошибка стенда» на строке (S9), `STOP_DANGER` — «есть, не нажат» (S10). Ошибки страницы в течение `web.click_response_s` после остановки не считаются (S2). `TabooViolation` наружу из обработчика не выходит.

**Слова опасных действий** — отдельно от `WEB_EXACT_WORDS`/`WEB_PREFIX_WORDS` (`taboo.py:159-247`). `http.py` их не вызывает: только браузерный путь, поэтому `check_web_request` не меняется, а проверки SD по галочке «разрушающие» работают как раньше. Подстрока: reboot, restart, shutdown, poweroff (ловит `sysreboot`). Начало слова: erase, wipe, purge, clear, delete, remove, перезагруз, перезапуст, выключ, форматир, удал, очист, стереть, стира (не «стер»: «Стерео»). Точное слово: format, formatsd, sdformat, reset. Точный адрес: `/api/sdcard/prepare` (форматирование «Рувер»). `format` не считается именем параметра (`?format=jpeg`, `/api/datetime?format=`, `"format":"H264"`), считается в пути и значении; `формат` как начало слова не берём: «Формат даты». Подпись проверяется только у кнопок и ссылок, значения в списках — нет. Страницы S9 и элементы S10 определяет `discover.py` по собранному контексту: подпись, `aria-label`, `name`, `id`, легенда, ближайший заголовок, открытая вкладка.

**Окно входа** (`login_window`): однократное, состояния `не открывалось → открыто → закрыто`, обратно нельзя. Открывает только `login.py` перед своим нажатием кнопки входа, когда во всех кадрах ровно одно видимое поле пароля и нет признаков S6. Закрывается при первом из: поле пароля исчезло, ответ отказа, `web.login_timeout_s`, появилось второе поле пароля. Пропускает до 4 изменяющих запросов к адресу камеры: у «Рувер» это `POST /api/auth/validate_session`, `POST /api/auth/challenge`, `POST /api/auth/login` (репозиторий прошивки, `www/src/views/LoginPage.vue:64`, `www/src/store/Authentication.ts:102,120`). `CAMERA_LOGIN_REQUESTS` не меняется: окно проверяет сам браузерный путь. `check_login_window` смотрит имена, а не значения: путь, ключи параметров и JSON; значения логина и пароля из тела убираются, иначе пароль `network1` сорвал бы вход. Из слов-признаков снимаются только слова входа (user, passw, pwd, pass, psw, login, logon, auth, credential, логин, парол, пользовател); остальные действуют. Запрет внутри окна: new, old, confirm, repeat, change, modify, set, reset, update, activate, register, recover, forgot; больше одного ключа пароля; пароль в теле дважды; нечитаемое тело с изменяющим методом.

**Вход.** Первая загрузка идёт без учётных данных: 401 с `WWW-Authenticate` → новый контекст с `http_credentials` (`origin` камеры), иначе форма. Успех: поле пароля исчезло и нет признаков отказа. Лимит сессий (409, «too many», «слишком много», `maxConnectionsAllowed`) → S18, память отказа не трогает. Смена пароля (два и более полей, слова new/confirm/activate) → S6. Отказ (401, 403, 423, слова «неверн», «заблокир», wrong, invalid, locked) и любой неясный исход (форма осталась) → S5: повтора нет, запись в `ctx.extra` под `rtsp_refusal.MEMORY_KEY`; в модуль добавляется функция с текстом без «для видео», `refused_password` проверяется до открытия браузера. **Выход:** элементы «выход», logout, signout обходом не нажимаются; в конце `logout_window` — одно нажатие, не больше 2 запросов, те же запреты. Нет кнопки → пометка в сводке.

**Окно записи** (`write_window(el)`): открывается только при `ctx.allow_writes` и закрытом журнале, до изменения поля, потому что часть интерфейсов сохраняет без кнопки. Закрывается по первому ответу или через `web.click_response_s`, не больше 5 запросов. Остальные нажатия и с галочкой идут как S7: действие без значения вернуть нечем (AD-3). У `vendor == ruver` запись идёт только при `web.ruver_writes = 1`, по умолчанию 0: галочка общая на весь сценарий. Меняются `select`, `checkbox`, `radio`, `role=switch`, `range`, `number`, `role=slider`, `role=combobox`. Другое значение: соседний доступный вариант, противоположное состояние, текущее ±шаг в пределах `min`/`max`, как `other_value` (`ruver.py:115`). Свободный текст, время, адреса, файлы, поля пароля не меняются: «пропущена». Порядок: чтение → журнал → окно → сохранение → перезагрузка страницы → чтение (и API у адаптера) → возврат тем же путём → сверка → журнал закрыт. Признаки перезагрузки (диалог, уведомление, `/api/service/need_reboot`) → S13. Расхождение после возврата → S14: запись на камере прекращена до конца прогона. После падения браузера сессия берётся из `storage_state`. Нового входа нет (S4): сессия потеряна → S14, пока директор не решит иначе (спорный пункт в отчёте Этапа 1).

**Обход.** Адрес — первый порт из `camera.port`, 80, 443, отдающий HTML; 80 и 443 закрыты и HTML нет → S17. Сертификат: `ignore_https_errors=True`, пометка в протоколе. Страница = адрес с `#…`, числа заменены на `{n}`, плюс цепочка вкладок и отпечаток заголовков и полей. Источники: `a[href]`, роли `link`, `tab`, `menuitem`, `treeitem`, элементы `nav`, все `iframe`. Переход по меню разрешён и на страницы S9: это чтение, запросы проверяются как всегда. Страница открывается заново адресом или повтором пути по меню, поэтому изменения в браузере не копятся. Элемент: роль, тег, тип, подпись, путь без индексов. Похожие: тот же ключ, цифры в подписи заменены на `#`; проверяется `web.same_elements_limit`. Недоступный: `disabled`, `aria-disabled`, `fieldset[disabled]`, `inert`, перекрыт другим элементом → «пропущена». Реакция: запрос, в том числе остановленный, смена адреса, диалог, изменение DOM вне областей, менявшихся за секунду покоя перед нажатием: часы и видео не считаются реакцией. Ошибки S2: `pageerror`, `console.error`, ответ камеры от 400, кроме `/favicon.ico`. Плагин: `object`, `embed`, предложение скачать `.exe`/`.msi` → S16. Ошибка `<video>` из-за кодека браузера → «пропущена», не S2. Сработал лимит → остаток перечисляется в `WEB-SUMMARY-1` (S19).

**Встраивание.** Один `CheckSpec`: `WEB-WALK-1`, `module="web"`, `phase=NETWORK`, `order=950` (после потока и API, `params.py:410`, `ruver.py:811`), `writes=False`, `group="Веб-интерфейс"`, `help_id="web"`, запись в `MODULES` (`checks/__init__.py:7`). `writes=True` не подходит: `skip_reason` снял бы весь обход (`checks.py:231`), поэтому галочку читает сама проверка (`checks.py:121`). Две проверки потребовали бы второго входа (S4). Родитель всегда `PASSED` с `children`, как `params.py:449`: при `FAILED` и пропаже связи `worker.py:181-188` заменяет результат и теряет строки, в том числе блокер S14. Строки: `WEB-LOGIN-1`, `WEB-PAGE-n`, `WEB-ELEM-n`, `WEB-WRITE-n`, `WEB-SUMMARY-1`; у каждой «прошла» — доказательство (`checks.py:269`). Дубли (тип, очищенный текст, адрес) сводятся к первой строке (S24). `timeout_s` = потолок 60 мин + запас 300 с, `web.walk_limit_min` ограничен потолком, как `common.py:33,69`: иначе `scheduler.py:324` снимет процесс посреди записи. Браузер и контекст свои в каждом рабочем процессе (`scheduler.py:130`, AD-2). «Стоп»: возврат записи (до `web.restore_timeout_s`) → выход до 1,5 с → закрытие до 2 с → удаление `qa-web-<место>-*` (`TMPDIR`, `TEMP`, `TMP` на время запуска драйвера). `Runner` при старте удаляет остатки.

**Данные.** База не меняется. Журнал: `<runs_dir>/pending-web/<адрес>_<порт>.json`, запись атомарная с `fsync`. Поля: `run_id`, `slot`, адрес и порт, `vendor`, адрес страницы без секретов, путь по меню, отпечаток элемента, подпись, тип, `old`, `new`, `stage` (`intent`, `sent`, `verified`, `restoring`), время. Папку передаёт `Runner` через `extra` (`scheduler.py:125`). Возврат только если поле найдено по отпечатку и сейчас показывает `new`: за тем же адресом могла оказаться другая камера. Пороги (`Threshold`, «стартовое значение»): `web.page_load_s` 5, `web.click_response_s` 2, `web.login_timeout_s` 15, `web.same_elements_limit` 3, `web.pages_limit` 100, `web.elements_limit` 1000, `web.walk_limit_min` 30, `web.writes_limit` 20, `web.restore_timeout_s` 20, `web.camera_return_s` 180, `web.ruver_writes` 0.

## Безопасность — backend-architect

Затронуто: пароль камеры, сессия, куки, токены. Точка входа: страницы и ответы камеры, недоверенные. MITRE ATLAS не применяется (`security.md:23`). Модель угроз: ошибка или незнакомая логика чужого интерфейса; интерфейс, намеренно обходящий браузерные меры, закрыт только двумя сетевыми слоями из таблицы.

| Обход | Как закрыт | Остаток |
|---|---|---|
| Всплывающие окна, `target=_blank` | `context.route` до первой страницы: `page.route` не видит первый запрос окна; окно записывается и закрывается | нет |
| Service Worker | `service_workers="block"`: `route` не видит его запросы | нет |
| Запрос без кадра: `keepalive`, `sendBeacon` при уходе со страницы, снятый `iframe`, `SharedWorker` | Playwright отпускает такой запрос без `route` (`crNetworkManager.ts`). Скрипт инициализации превращает `sendBeacon` и `keepalive` в обычный `fetch`, убирает `SharedWorker` | скрипт — не граница; проверяется ловушками mock до остальных задач |
| WebSocket страницы | `route_web_socket`: адрес по общим правилам; сообщения страницы только через `on_message`; камера → страница свободно. Текст: табу, опасные слова, `is_write_message`, при нажатии ещё `is_web_action`. Двоичное от страницы не отправляется: проверить нельзя | подписка на видео с глаголом останавливается, видео не покажется |
| WebSocket из воркера | `route_web_socket` подменяет конструктор только в окне страницы. Сокет виден в `page.on("websocket")`, но не в обработчике → нажатия на странице прекращаются, «пропущена» | сообщения уже открытого сокета не остановить |
| WebRTC, WebTransport | скрипт инициализации убирает `RTCPeerConnection`, `WebTransport` | такое видео не покажется |
| Перенаправление записи (307 POST) | `route` редиректы не видит, а `continue_` не применяется к записи: только `route.fetch(max_redirects=0)`. Каждый адрес `Location` проходит решение заново. XHR: цепочка до 5 шагов внутри обработчика. Документ: 3xx заменяется страницей `meta refresh`, переход идёт новым запросом. 307/308 документа и смена схемы → `STOP_WRITE`. `route.fetch` умеет только Basic, поэтому Digest считает `digest.py`; алгоритм кроме MD5 → «пропущена» | нет |
| Перенаправление чтения | чтение идёт через `continue_`: `route.fetch` буферизует и повис бы на MJPEG. `context.on("request")` проверяет `redirected_from`; запрещённое → «ошибка стенда», нажатия на странице прекращаются | чтение, перенаправленное камерой на действие в ней же, уходит; видно только после факта |
| Чужие хосты | правило 1 плюс второй слой: `proxy` на закрытый `127.0.0.1:9`, `bypass` — адрес камеры. Перенаправления и подресурсы на другой хост никуда не дойдут | loopback Chromium не проксирует: на mock слой проверяется именем `foreign.test` |
| GET с неизвестным глаголом | при нажатии: `is_web_action` (start, stop, enable, disable, trigger, move, run, exec, cmd, ptz, goto, toggle) и правило «такого GET не было при спокойной загрузке»; опасные слова — на любом GET | автоматический GET при открытии страницы проходит, как у обычного посетителя |
| Загрузка файлов | `accept_downloads=False`; файл в протокол не берётся | нет |
| Выбор файла | `input[type=file]` не нажимается, `set_input_files` нет в фасаде, `filechooser` записывается | нет |
| `alert`, `confirm`, `prompt`, `beforeunload` | обработчик обязан ответить, иначе нажатие зависнет. `alert` и `beforeunload` — принять; `prompt` — отклонить; `confirm` — отклонить, в окне записи принять, если нет опасных и запретных слов. Текст идёт в строку; признак перезагрузки → S13 | нет |
| HTTP-авторизация | Playwright считает попытку на запрос, поэтому при неверном пароле каждый подресурс расходовал бы счётчик. Учётные данные только в контексте с 401, только `origin` камеры; первая навигация одна; второй 401 → все запросы контекста обрываются | нет |
| Прямой запрос мимо браузера | фасад `BrowserSession`; `tests/test_architecture.py`: `playwright` в `NETWORK_MODULES`, запись в `ALLOWED`, запрет `.request` и `.route` вне `browser.py` | нет |

**Секреты (S22).** `_PATTERNS` дополняются `sid`, `hash`, `nonce`, `cnonce`, `digest`. `store.py:119` не знает пароля, поэтому `walk.py` очищает тексты сам: `redact(text, [ctx.password, *значения куки и токенов сессии])`; значения короче 6 символов не берутся. Журнал обхода хранит метод, адрес, код; тела и заголовки не хранятся. Двоичные снимки пишутся без очистки (`store.py:116`), поэтому: `mask` на всех `input[type=password]`, нет снимка от заполнения формы входа до закрытия окна входа, нет снимков на страницах S9 (там видны ключи и пароли открытым текстом), снимок только у непрошедших строк. `storage_state` — только в памяти для новой сессии после падения браузера, на диск не пишется. HAR, трассировка и видео выключены. Пароль вводится только `fill` в поле, в адрес и командную строку не попадает.

**Недоверенные данные.** Заголовки, подписи, текст консоли: убрать управляющие символы и символы направления письма, ограничить 200 символами. HTML-протокол экранирует сам (`report/html.py:9`); имена файлов очищает `safe_name` (`store.py:37`), но в них идут только номера. Адреса со страниц открываются только после правила 1. Песочница Chromium: Playwright по умолчанию её выключает, а браузер исполняет код камеры. Windows — `chromium_sandbox=True`; Linux — включить, если запускается на Ubuntu 22.04 и 24.04, иначе риск записать в `security.md`. Браузер закреплён версией, новые зависимости проходят pip-audit (`ci.yml:49`).

**Поправка AD-7 (текст для `architecture.md`, задача T1).** Для браузера есть второй выход к камере — `drivers/camera/browser.py`, единственный модуль с `playwright`. Он работает вместо `http.py`, но под теми же проверками `core/taboo.py`; перехват стоит на всём контексте браузера и на WebSocket; запрос на адрес не из списка стенда не отправляется. Вход: для камеры без адаптера одно окно входа за обход; его открывает программа перед своим нажатием кнопки входа, до начала обхода, когда на странице одно поле пароля и нет признаков смены пароля. Внутри окна снимаются только слова входа и только в именах, до 4 изменяющих запросов; признаки смены пароля, опасные действия и `check_http`, `check_onvif` действуют. После отказа камеры вход не повторяется ни одной проверкой прогона. Опасные действия (перезагрузка, выключение, форматирование, удаление, очистка) через браузер не выполняются ни при каких галочках; проверки SD по галочке «разрушающие» идут через `http.py` и этот список их не касается. Запись через браузер: только в окне записи, при галочке «изменяющие», с журналом и возвратом; остальное останавливается и записывается в протокол. `CAMERA_LOGIN_REQUESTS` остаётся точным списком для `http.py`.
