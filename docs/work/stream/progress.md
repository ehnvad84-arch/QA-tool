## Ревью, круг 2, 05.11

Вердикт request-changes: 3 blocker, 3 major, 7 minor, старый долг. CI коммита 3f579b8 зелёный, но сборку 0.4.1 из него не выкладывали.

- 25: открытие потоков камеры по очереди под общей блокировкой, проверка отказа внутри неё.
- 26: `RtspClient.rejected`: после отказа TEARDOWN не идёт; `WatchEnd.REFUSED`, отказ на удержании запоминается и останавливает все потоки камеры. Первое удержание потоков разнесено на `PING_SPREAD_S`: при сроке сессии меньше 3 с на поток разнос сжимается, и соседи могут успеть по запросу; это предел решения.
- 27: тишина считается только по каналу видео; строка «видео шло N с из M» по времени удержания; сброс меток (серия назад длиннее `MAX_B_RUN`) — `time_jumps`.
- 28: порог пропуска с кадрами B — на кадр дальше законного шага; счёт приближённый, отдельный выпавший кадр B виден только в частоте.
- 29: `worst_growth`: худшее окно в час вместо среднего за срок.
- 30: 0 пакетов при TIME_UP — тоже «UDP не дошёл».
- 31: шаблон адреса останавливается на кавычках и тегах; запасной вариант маскирует до первого @, в однострочном SOAP это может съесть кусок: лучше потерять кусок доказательства, чем пароль.
- 32: неверный порт и IPv6 в `to_stand_address`. 33: 403 считается отказом. 34: общий срок в `_read_response` учитывает и обрывки. 35: удвоенный размер буфера на Linux. 36: таймаут открытия 5 с, «Стоп» при первом открытии — «пропущена». 37: `step_ms` удалён.
- О2, О3, О5, О6, О7 закрыты: логин с @; порт стенда важнее ответа камеры; пределы длины в шаблоне; канал из ответа в архиве и метаданных; память отказа вынесена в `checks/rtsp_refusal.py` и работает в `RUV-S-STREAM-1`, архиве и метаданных.
