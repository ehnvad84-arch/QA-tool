## Зачем — главная сессия

Сейчас настройки изображения камер проверяют глазами в веб-интерфейсе: субъективно, долго, и ошибки прошивки (ползунок ничего не меняет или меняет не в ту сторону) доходят до заказчика. Нужно: для каждой камеры программа проводит каждую настройку изображения через положения 0 %, 50 % и 100 % её диапазона, снимает кадр в каждом и делает вывод «эффект есть / нет / обратный» по измеримой величине; затем сравнивает камеры между собой. Управляемого света и тестовых таблиц пока нет (этап 6 после этапов 7–9), но движок сразу готов принять их.

## Поведение (BDD) — главная сессия

Не забудь ошибки и граничные случаи. -->

Настройки этапа: яркость, контраст, насыщенность, резкость, баланс белого (усиление красного и синего в ручном режиме), WDR, компенсация засветки, шумоподавление — всё, что камера объявляет в ONVIF Imaging. Положение «N %» — точка `min + N % × (max − min)` диапазона, который объявила сама камера.

### S1: настройка даёт эффект

- **Дано** камера объявляет настройку и её диапазон, галочка «изменяющие» включена, сцена неподвижна
- **Когда** программа ставит 0 %, 50 %, 100 % и в каждом положении снимает кадр
- **Тогда** величина настройки (по таблице правил) меняется в ожидаемую сторону на каждом шаге больше порога → «прошла», в протоколе три снимка и три значения

### S2: эффекта нет

- **Дано** как в S1
- **Когда** величина между 0 % и 100 % изменилась меньше порога
- **Тогда** «не прошла»: «настройка не меняет изображение», три снимка и значения в доказательстве

### S3: эффект обратный или неровный

- **Дано** как в S1
- **Когда** величина меняется в обратную сторону или между 0 % и 50 % и между 50 % и 100 % идёт в разные стороны
- **Тогда** «не прошла» с указанием, на каком шаге и куда

### S4: автоэкспозиция гасит эффект

- **Дано** у камеры включена автоматическая экспозиция, настройка из списка, на который она влияет (яркость, контраст, компенсация засветки, WDR)
- **Когда** эффекта нет
- **Тогда** «пропущена», а не «не прошла»; пояснение для инженера: что автоэкспозиция возвращает яркость кадра обратно, как выключить её вручную на камере и повторить, и что программа сама режим экспозиции не меняет

### S5: сцена нестабильна

- **Дано** перед настройкой программа дважды снимает кадр «до» без изменений
- **Когда** эти два кадра различаются больше порога (мигает свет, движение в кадре)
- **Тогда** настройка получает «ошибку стенда» с объяснением; задачи программистам нет

### S6: настройка не поддерживается или отвергнута

- **Дано** камера не объявляет настройку, или объявляет без диапазона
- **Тогда** «пропущена» с причиной
- **Дано** камера объявляет настройку, но отказывает в установке значения из своего же диапазона или читается другое значение
- **Тогда** «не прошла»: «камера не приняла значение из объявленного диапазона»

### S7: без галочки «изменяющие»

- **Дано** галочка выключена
- **Тогда** настройки не меняются, строки «пропущена: не разрешено сценарием»; снимок текущего кадра и текущие значения настроек всё равно попадают в протокол и сравнение

### S8: возврат настроек

- **Дано** проверка меняла настройки
- **Когда** она закончилась любым исходом, в том числе ошибкой
- **Тогда** все значения возвращены и сверены (AD-3); не вернулось → важность «блокер», в протоколе какая настройка, было, осталось

### S9: камера пропала посреди проверки

- **Тогда** «не прошла» по правилам планировщика (камера перестала отвечать), попытка вернуть значения при появлении; не вышло → S8

### S10: сравнение камер

- **Дано** в прогоне несколько камер
- **Когда** проверка картинки прошла у них
- **Тогда** отчёт сравнения: по каждой настройке снимки всех камер в положениях 0 %, 50 %, 100 % рядом, график величины по камерам и итог «эффект есть / нет / обратный»; камеры с разным диапазоном сравниваются по процентам диапазона, а не по абсолютным значениям

### S11: таблица правил

- **Дано** инженер хочет поменять порог или ожидаемую сторону для настройки
- **Тогда** он меняет её в конфигурации порогов без правки кода; в протоколе у каждой строки указан порог и его источник

## Вне рамок — главная сессия

- Экспозиция, ИК-фильтр, день/ночь, фокус и объектив — этап 6 (нужен свет и тёмная комната).
- Качество картинки по тестовым таблицам (резкость по ISO 12233, цвет по ColorChecker) — после этапа 6; движок готов принять «сцену с таблицей и светом».
- Запись настроек через веб-интерфейс и API адаптера — не в первой версии: только ONVIF Imaging.
- Режим экспозиции программа не меняет никогда, даже с галочкой: это меняло бы условия всех остальных настроек.
