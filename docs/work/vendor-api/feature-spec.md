# Спецификация: vendor-api

Статус: черновик <!-- → утверждена (Гейт 1) -->
PRD: docs/ROADMAP.md, этап 3; AD-4 (адаптеры производителей), AD-3, AD-7

## Зачем — главная сессия

ONVIF не видит большую часть настроек камеры «Рувер». Нужно проверить её собственное API: каждая операция отвечает по описанию, а записанная настройка читается обратно и возвращается как была. Заодно появляется механизм адаптеров: следующие производители подключаются так же (AD-4).

## Что известно из разбора источников (2026-11-04)

- Описание `ruware-api-release-0.5.4.json` устарело: 55 адресов интерфейса камеры 0.6.14 в нём нет, 41 адрес описания интерфейс не использует.
- Основа — `www/openapi/doc/openapi.yaml` из репозитория прошивки: версия 0.6.7_p4, 203 адреса, все есть в интерфейсе камеры, в интерфейсе сверх него 12 адресов.
- Вход: `GET /api/auth/create_session`, затем `POST /api/auth/login` с паролем `MD5(пароль:идентификатор сеанса)`, дальше заголовок `X-Session-ID`. Камера держит не больше 3 сеансов, неверный пароль расходует счётчик попыток.
- Чтение — GET, но часть чтения идёт через POST (`/api/manifest`, `/api/sdcard/files`, `/api/service/log`, `/api/service/export_settings`, `/api/service/need_reboot`): метод не определяет, изменяет ли операция настройку.
- Табу по описанию 0.5.4 закрывает 35 изменяющих операций из 149. Прореха: настройки NTP в API открыты, хотя в ONVIF `SetNTP` запрещён.

## Поведение (BDD) — главная сессия

### S1: Вход и сеанс

- **Дано** камера «Рувер» с верным паролем
- **Когда** начинается модуль API
- **Тогда** программа открывает один сеанс на камеру на весь модуль и закрывает его в конце, в том числе при сбое и остановке

### S2: Неверный пароль

- **Дано** камера не приняла пароль на CORE-CONNECT-1 или на входе в API
- **Тогда** входов больше нет, строки API «пропущена», задач нет; всего не больше одной попытки входа в API за прогон

### S3: Нет свободного сеанса

- **Дано** на камере заняты все 3 сеанса
- **Тогда** строки API — «ошибка стенда» с причиной «нет свободного сеанса», задач нет

### S4: Чтение всех настроек

- **Дано** изменяющие проверки выключены
- **Когда** идёт модуль API
- **Тогда** каждая читающая операция вызвана один раз; ответ 200 и совпадение со схемой описания — «прошла», иначе «не прошла» с запросом и ответом в доказательствах

### S5: Операция, которой нет в этой прошивке

- **Дано** операция есть в описании, но камера отвечает 404
- **Тогда** «пропущена» с причиной «нет в прошивке <версия>», а не задача программистам

### S6: Записал — прочитал — вернул

- **Дано** разрешены изменяющие проверки
- **Когда** проверка меняет настройку на другое допустимое значение
- **Тогда** чтение возвращает новое значение, затем исходное значение возвращается и сверяется. Несовпадение — «не прошла»; значение не вернулось — «не прошла» с причиной «камера осталась изменённой»

### S7: Недопустимое значение

- **Дано** разрешены изменяющие проверки и описание задаёт пределы
- **Когда** отправлено значение вне пределов
- **Тогда** камера отвечает ошибкой, значение не меняется; принятое значение — «не прошла», настройка возвращается

### S8: Табу

- **Дано** операция меняет сеть, учётные записи, NTP, сброс или импорт настроек
- **Тогда** она не отправляется никогда, ни с какой галочкой; в протоколе «пропущена: запрещено табу»

### S9: Разрушающие операции

- **Дано** перезагрузка, форматирование и подготовка карты, удаление записей, удаление всех событий
- **Тогда** без галочки «разрушающие» не отправляются: «пропущена: не разрешено сценарием»

### S10: Вид в окне и протоколе

- **Дано** модуль закончился
- **Тогда** в ходе проверки одна строка на раздел API («Изображение: 51 операция»), в протоколе строка на каждую операцию, в задачах — только «не прошла»

### S11: Камера другого производителя

- **Дано** камера без адаптера
- **Тогда** строк API нет, общий слой работает как раньше (AD-4)

## Вне рамок — главная сессия

- Проверка эффекта настройки на картинке (этап 7) и поток (этап 4).
- Адаптеры других производителей: только механизм.
- `/api/recorder` как замена архива ONVIF: чтение — да, проигрывание — нет.

## UI — главная сессия

Новых экранов нет. Модуль «API производителя» появляется на «Сценарии» с группами по разделам API; для камер без адаптера он неактивен, как проверки чужого производителя.

## Архитектура, API и данные — главная сессия

- `scripts/gen_api_map.py` — разбирает `openapi.yaml` из репозитория прошивки и пишет `src/qa_tool/data/ruver_api_map.json`: адрес, метод, вид (чтение, запись, табу, разрушающая), параметры, пределы, схема ответа. В репозиторий идёт наша карта, а не файл прошивки (never.md). Ручные поправки — в отдельной таблице скрипта, с причиной.
- `drivers/camera/ruver/client.py` — `RuverClient`: сеанс и вызовы только через `drivers/camera/http.request` (табу, AD-7). Контекстный менеджер закрывает сеанс при любом исходе.
- `checks/api/ruver.py` — составные проверки по разделам: `API-<РАЗДЕЛ>-READ`, `API-<РАЗДЕЛ>-WRITE`; строки — через `ChildResult`, как у onvif-tt. Вход один раз на модуль: состояние в процессе камеры.
- `core/taboo.py` — закрыть NTP и источник времени в API, `/api/datetime` целиком; сверить список с картой тестом: каждая операция карты либо чтение, либо записана по виду.
- Проверка схем — `jsonschema`. schemathesis из стека не берём: он сам шлёт запросы мимо `http.py` (AD-7).
- Адаптер выбирается полем `Camera.vendor`; `CheckSpec.vendors` уже отсекает чужие камеры (`core/checks.py:152`).

## Безопасность — главная сессия

- Пароль только как MD5 с сеансом; идентификатор сеанса вырезается из доказательств (`X-Session-ID` добавить в `redact`).
- Ответы `/api/configuration`, `/api/service/export_settings`, `/api/users/*` могут содержать секреты: в доказательства — только после `redact`, снимок настроек — в памяти.
- Новая зависимость `jsonschema` — через pip-audit в CI.
- Угроза: новая прошивка с новым опасным адресом. Защита — операция не из карты не вызывается вовсе.

## Решения — главная сессия

| Вопрос | Выбрано | Почему | Отвергнуто |
|---|---|---|---|
| Источник описания | `openapi.yaml` 0.6.7_p4, карта генерируется | ближе всего к 0.6.14 | `ruware-api-release-0.5.4.json`: 55 адресов нет |
| Обход API | свой, через `http.py` | табу не обойти | schemathesis: шлёт запросы сам |
| Неописанные операции | не вызываются | неизвестный адрес может быть опасным | вызывать всё из интерфейса |
