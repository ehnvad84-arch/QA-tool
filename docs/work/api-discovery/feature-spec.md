## Зачем — главная сессия

Родной API чужих камер (Hikvision ISAPI, Dahua CGI/RPC2, Tiandy, Beward) программисты сейчас разбирают руками по веб-интерфейсу, PDF вендоров и трафику браузера — часы и дни на модель (директор 09.11). Нужна карта родного API каждой подключённой камеры (разделы, параметры, допустимые значения, текущие значения) и сверка с ONVIF: одна и та же настройка в родном API и в ONVIF читается одинаково, иначе — задача программистам (живой случай 09.11: Hikvision .111 — ONVIF Exposure AUTO, ISAPI ExposureType manual; ONVIF MaxGain = ISAPI GainLevel). Таблица соответствий «ONVIF ↔ родной параметр» строится программой сама (директор 09.11, вариант C), для всех брендов стенда сразу. Карты копятся «на будущее»: на них потом встанут сравнение прошивок и адаптеры производителей (AD-4).

## Поведение (BDD) — главная сессия

Живые образцы 09.11 (только чтение, через туннель стенда): Hikvision .114 — ISAPI `capabilities` 13 разделов из 18, ~170 параметров с допустимыми значениями; Dahua .108 — CGI `configManager getConfig` и `encode getConfigCaps`, ~900 параметров изображения, входа видео, кодирования и наложений; веб-обход как источник трафика через туннель почти не дал данных (Dahua — пустая страница, Tiandy — плагин браузера, Beward — нет формы входа). Значит, основной источник — самоописание API, трафик веб-обхода — запасной.

### S1: карта родного API камеры

- **Дано** камера, у бренда которой есть сборщик (Hikvision, Dahua, Ruware, Tiandy, Beward), галочка «изменяющие» не важна
- **Когда** в прогоне идёт проверка «API камеры»
- **Тогда** в папке прогона — `api-map.json`, в протоколе — приложение «API камеры»: модель и прошивка, разделы, параметры, тип, допустимые значения, текущее значение; строка «прошла: карта снята, разделов N, параметров M»; значения разделов сети, пользователей и безопасности не сохраняются — только их описание; пароли, ключи, токены вырезаются

### S2: бренд без самоописания или без сборщика

- **Дано** камера, родной API которой программа не умеет читать напрямую
- **Тогда** карта строится из трафика веб-обхода того же прогона (адреса, методы, поля), если обход был и дошёл дальше страницы входа; иначе — только ONVIF, строка «пропущена: родной API не найден — нет сборщика для бренда и трафика веб-обхода»

### S3: сверка родного API с ONVIF

- **Дано** карта снята и для бренда есть таблица соответствий «ONVIF ↔ родной параметр» (с переводом шкалы)
- **Тогда** для каждой пары: значения совпадают с учётом шкалы → строка пары «прошла»; не совпадают → «не прошла» с обоими значениями и путями (пример: «ONVIF Exposure/Mode = AUTO, ISAPI Image/Exposure/ExposureType = manual»), задача программистам; объявленные диапазоны тоже сверяются (пример: Dahua .108 — ONVIF и CGI объявляют 512…5632 кбит/с, а H.264 держит 1792)

### S4: автопоиск соответствий (вариант C)

- **Дано** галочка «изменяющие», камера из списка стенда
- **Когда** программа по очереди меняет настройку из списка ONVIF (картинка: яркость, контраст, насыщенность, резкость, баланс белого, WDR, BLC; кодировщик: битрейт, кодек) на другое значение в её диапазоне
- **Тогда** перед и после каждой записи снимается карта родного API; параметры, сдвинувшиеся вслед за записью, — кандидаты; пара подтверждается второй записью другого значения и считается найденной, если сдвинулся ровно один родной параметр и его значения ложатся на шкалу ONVIF; после каждой настройки — возврат по ONVIF и сверка всей карты с исходной; найденные пары — в таблицу соответствий прогона с источником «найдено автоматически, прогон <номер>»

### S5: побочный эффект записи

- **Когда** после записи сдвинулось больше одного родного параметра или параметр вне ожидаемого раздела (как MaxGain на Hikvision .111 09.11)
- **Тогда** автопоиск на этой камере останавливается, программа возвращает всё, что меняла, сверяет всю карту; не вернулось — строка возврата «не прошла» (блокер) с каждым параметром «было / осталось» и путём в родном API, чтобы вернуть вручную

### S6: без галочки «изменяющие»

- **Тогда** автопоиска нет; сверка S3 идёт по таблице соответствий из библиотеки (найденной прошлыми прогонами той же модели и прошивки или подтверждённой вручную); таблицы нет — строки сверки «пропущена: нет таблицы соответствий для модели — нужен прогон с галочкой «изменяющие»»

### S7: библиотека карт и соответствий

- **Дано** прогон нашёл карту и пары
- **Тогда** они сохраняются в библиотеку рядом с папкой прогонов по производителю, модели и прошивке; следующий прогон той же модели берёт пары оттуда (S6); в протоколе указано, откуда пара: «найдено в прогоне …» или «подтверждено вручную»

### S8: вход в родной API

- **Когда** камера отвергает вход в родной API
- **Тогда** повтора нет (одна попытка на прогон, как в веб-обходе и ONVIF), строки родного API — «ошибка стенда: вход в родной API отвергнут», ONVIF-часть и остальные проверки идут; на часы и способ входа (Basic, Digest) — та же логика, что у ONVIF

### S9: табу

- **Дано** сборщик или автопоиск собирается отправить запрос
- **Тогда** каждый запрос — через `drivers/camera/http.py` с проверками `core/taboo.py`; изменяющий запрос к разделам сети, пользователей, безопасности, сброса, обновления, импорта — не уходит ни при каких галочках; автопоиск пишет только по ONVIF и только настройки из списка S4

## Вне рамок — главная сессия

- Сравнение карт разных прошивок одной модели и заготовки адаптеров — следующая итерация; формат карты под них рассчитан.
- Запись через родной API, кроме поиска соответствий (вариант C), — только через адаптер производителя с журналом и возвратом.
- Документы вендоров в репозитории — только ссылки.

### Протокол камеры: «Приложение N. API камеры: карта и сверка с ONVIF»

Пар нет (S6) — вместо таблицы одна строка `API-MATCH-0` с причиной.

Без галочки — строка «Автопоиск не запускался: изменяющие проверки запрещены сценарием».
6. **Разделы карты** (обзор, без параметров; 8 pt): «раздел · класс (картинка, кодировщик, наложения, события, система, сеть и безопасность, прочее) · параметров · в парах · расхождений · примечание («только описание: раздел сети», «не ответил: 404 — раздела нет у модели», «скрыто 1 значение», «! не вернулась выдержка»)», ≤ 25 строк. Под таблицей — «Параметры, допустимые и текущие значения — в документе «Карта API QA-…-3» (экран «Протоколы», строка «Карта API»; файлы api_map_3.pdf, .xlsx, .html в папке прогона).»

`<thead>` у сверки — повторяется на каждом листе PDF. Пути — как отдала камера (их копируют для ручной проверки), простым текстом с экранированием; перенос — только там, где Qt сам рвёт строку (проверить печатью: после «/» и «.»); не рвёт — шаблон делит путь на строки по «/».

HTML — тот же шаблон с `media="html"`, широкие таблицы — в обёртке с прокруткой. Excel протокола — два листа (в имени листа нельзя «:»), автофильтр, заголовок закреплён; числа — числами, текст — текстом, у значения два столбца «число» и «текст», чтобы столбец был одного типа и фильтр работал:
- **«Сверка API»** — строка на `API-MATCH`/`API-RANGE`: ID · n · настройка · ONVIF путь · значение число / текст · диапазон мин / макс · родной путь · значение число / текст · допустимые мин / макс · вид шкалы · a · b · ожидалось · допуск · фактический предел · итог (заливка) · важность · причина · откуда пара · прогон-источник · прошивка-источник.
- **«Пары API»** — таблица соответствий прогона и ход автопоиска, строка на «настройка × сдвинувшийся параметр × запись» (известные пары без поиска — строкой без записей; листы ONVIF из `O` — строками с «родной API» пусто): настройка ONVIF · n · путь ONVIF · номер записи · ONVIF было · записано · прочитано · сдвинувшийся параметр (родной или ONVIF) · копий · было · стало · после возврата · вернулся родным API (да/нет) · вернулось (да/нет) · пара (найдена / кандидат / не найдена / не искали) · вид шкалы · a · b · источник · прогон. Блокер — фильтр «вернулось = нет».

### Документ «Карта API» (`api_map_<место>.html/.pdf/.xlsx`)

Выпускается рядом с протоколом камеры, если `API-MAP-1` «прошла» (самоописание или трафик); шаблон `report/templates/api_map.html` с `_style.html`, PDF — тем же `write_pdf`, A4 альбомная. Справочный документ: подписей и итогов нет — они в протоколе. Hikvision ≈ 5 листов, Dahua ≈ 7–8 после свёртки; предела строк в PDF нет (размер ограничивает сама карта: ≤ 5000 параметров, иначе «обрезано» по «Архитектуре»).

1. **Шапка** — как у протокола: «КАРТА РОДНОГО API КАМЕРЫ · QA-…-3», «прогон · снята · qa-tool», таблица «камера · производитель · модель и прошивка (ONVIF; по родному API, если отличается) · адрес · место · родной API, сборщик и версия · источник · вход». Строка «Итоги, пары с ONVIF и задачи — в протоколе QA-…-3, Приложение 3.» Карта обрезана — плашка `.note` под шапкой: «Карта обрезана: <причина>; снято N разделов из M».
2. **«Как читать»** (рамка `#f6f6f6`): типы («число 0…100», «список», «да / нет», «текст до 32 знаков», «только чтение»), свёртка `[*]`, «скрыто», «только описание», ссылки «п. 3, API-MATCH-12» ведут в протокол.
3. **Разделы** — та же таблица, что п. 5 приложения, плюс не ответившие запросы («GET /ISAPI/System/Audio/channels/1/capabilities · 404 · раздела нет у модели»).
4. **Карта** (с новой страницы, 8 pt, `thead` повторяется): строка-заголовок раздела (`th colspan`, «Image · картинка · GET /ISAPI/Image/channels/1 · 46 параметров»), под ней «параметр (путь внутри раздела) · тип и допустимые значения («число 0…100», «список: auto, manual» — длиннее 8 значений: первые 3, «…», последнее и «(18 значений)»; «не объявлены»; «негодный: min > max») · текущее · примечание («пара: яркость, API-MATCH-1», «! расхождение с ONVIF — протокол, п. 3, API-MATCH-12», «! не вернулось: было 1/50», «скрыто: пароль», «меняется сам»)». Повторы по каналам, профилям и потокам с одинаковыми допустимыми значениями свёрнуты в строку `[*]`, текущее — «[0] 50 · [1] 50 · [2] 60»; различаются допустимые — отдельные строки. Чувствительный раздел — заголовок с «только описание» и одна строка «Раздел сети: значения не читались и не сохранялись. Имена и допустимые значения — в Excel, лист «Параметры»». Источник «трафик» — заголовок раздела «метод и адрес», допустимые — «не видны в трафике»; запрос, остановленный табу, — строкой «запись замечена, остановлена табу», без значений.

HTML (`media="html"`): раздел карты — `<details>`, раскрыты разделы с парами и расхождениями; сверху — ссылки на разделы и на `protocol_<место>.html`. Excel `api_map_<место>.xlsx`, три листа, автофильтр, заголовок закреплён, числа — числами:
- **«Разделы»** — раздел · класс · запрос чтения · запрос описания · код · байт · чувствительность · параметров · в парах · расхождений.
- **«Параметры»** — строка на параметр без свёртки: раздел · параметр (полный id) · индекс · тип · минимум · максимум · шаг · допустимые (через «; ») · длина макс · только чтение (да/нет) · текущее, число · текущее, текст («скрыто» / «не сохраняется») · чувствительность (обычный / чувствительный / секрет) · меняется сам (да/нет) · в паре с ONVIF (n, настройка) · источник (самоописание / трафик).
- **«Ошибки»** — запрос · код · причина.

### Компоненты, токены, доступность, адаптивность

- Окно — только существующее: пункты списка производителей и подсказки окна «Камера на место», строка дерева, подпись под галочкой (поля `CheckSpec`), строка хода, правило `Step.label`, строка документа «Карта API» в `protocols.py` (по образцу `IMAGE_COMPARE`/`CODEC_COMPARE`: константа префикса, подсказка в `TIPS`, проверка наличия `.html`); новых цветов нет.
- Отчёты — новое: `templates/_api.html` (приложение), `templates/api_map.html` (документ), выпуск документа рядом с протоколом камеры в `publish.py`, листы протокола и книга карты в `xlsx.py`. Стили — `_style.html`, `.alarm`, `.note`, `.bad`, `.st-*`, заливки `xlsx.py`. Новое в `_style.html` — два класса без цвета: `.small { font-size: 8pt }` — плотность карты и обзора разделов (40 строк на лист вместо 30); `.path` — моноширинный «DejaVu Sans Mono» (в сборке уже есть DejaVu Sans; Windows — Consolas): в путях API различаются I/l/1 и O/0, путь переписывают руками при ручном возврате.
- Доступность: подсказка и F1 у каждого нового элемента; статус всегда словом; расхождение — цвет + жирный + «!»; картинок и графиков нет; самый мелкий текст 8 pt; всё от камеры (пути, значения, имена разделов) — простым текстом с экранированием, в имена файлов не идёт.
- Адаптивность: в окне — перенос по словам, длинный путь в строке хода укорачивается слева; PDF — A4 альбомная, `thead` повторяется; HTML — 1366–1920 px, таблицы шире окна прокручиваются в своей обёртке; Excel — ширины: путь 48, допустимые 40, причина 60, прочие 12–16, перенос как у существующих листов.

### Модель карты и `api-map.json` (версия 1)

Карта → разделы → параметры. **Раздел** — один ресурс родного API: адрес ISAPI, имя конфигурации CGI, операция OpenAPI. **Параметр** — лист раздела. Ключи — по-русски, как в `measure.json` «Кодеков».

```json
{
 "формат": "qa-tool/api-map", "версия": 1,
 "сборщик": {"бренд": "hikvision", "имя": "ISAPI", "версия": 1},
 "источник": "самоописание",
 "камера": {"производитель": "…", "модель": "…", "прошивка": "…"},
 "прогон": "QA-20261109-003", "место": 2, "время": "2026-11-09T10:12:00+00:00",
 "вход": "Digest MD5",
 "разделы": [{
   "id": "Image/channels/1", "класс": "картинка",
   "чтение": "GET /ISAPI/Image/channels/1",
   "описание": "GET /ISAPI/Image/channels/1/capabilities",
   "код": 200, "байт": 3512, "чувствительность": "обычный",
   "параметры": [{
     "id": "Image/channels/1/Color/brightnessLevel",
     "тип": "целое", "допустимые": {"мин": 0, "макс": 100},
     "значение": "50", "чувствительность": "обычный", "изменчивый": false
   }]
 }],
 "ошибки": [{"запрос": "GET /ISAPI/System/Audio/channels/1/capabilities", "код": 404,
             "причина": "раздела нет у модели"}],
 "пределы": {"обрезано": false, "причина": ""}
}
```

- `источник`: «самоописание» | «трафик веб-обхода». `класс` раздела: «картинка», «кодировщик», «наложения», «события», «система», «сеть и безопасность», «прочее» — от сборщика; по нему S4 решает «ожидаемый раздел».
- `id` параметра устойчив между прошивками (на нём встанет сравнение прошивок): Hikvision — путь ресурса без `/ISAPI/` и локальные имена элементов, повторы — `[i]` (`…/TextOverlay[2]/enabled`); Dahua и Beward — ключ камеры без `table.` (`VideoColor[0][0].Brightness`); «Рувер» — `<путь операции>#<JSON-указатель>`. Свёртка повторов `[*]` — дело протокола, в файле параметры раздельно.
- `тип`: «целое», «число», «логический», «перечисление», «строка», «объект» (лист без значения), «неизвестно». `допустимые`: `{"мин","макс","шаг"}` | `{"значения": […]}` | `{"длина_макс": n}` | `null` («не объявлены») | `{"негодный": "<причина>"}`; признак «только чтение» — `"запись": false`, если сборщик это знает.
- `значение` — строка как у камеры; `null` — не читалось, чувствительный параметр или секрет.
- `чувствительность`: «обычный»; «чувствительный» — сеть, учётные записи, безопасность, время и NTP, облако и P2P, почта, FTP, SNMP, мультикаст: значение не сохраняется, только описание; «секрет» — пароли, ключи, токены, соли, сертификаты: значение отбрасывается при разборе и в снимки не попадает. Правило: класс раздела от сборщика («сеть и безопасность»), затем слова пути параметра через `taboo.web_forbidden_word` (тот же широкий список, что у веб-обхода) плюс «multicast», «email», «smtp», «ftp»; секрет — `pass(word|wd|phrase)?|pwd|psw|secret|token|salt|credential|cert|psk|private.?key|api.?key|encrypt.?key` по словам camelCase (`keyFrameInterval` — не секрет). Чувствительность раздела наследуется вниз, параметр её не понижает.
- `изменчивый`: менялся между двумя исходными снимками без записи или помечен сборщиком (состояние, счётчики, время). В S4 и S5 не участвует.
- Паспортные значения (серийный, MAC, имя устройства) в карту не идут значениями: MAC — «сеть», серийный и имя — уже в шапке протокола.

`api-pairs.json` (версия 1) — таблица соответствий прогона; тот же формат у библиотеки и ручных таблиц:

```json
{"формат": "qa-tool/api-pairs", "версия": 1,
 "камера": {"производитель": "…", "модель": "…", "прошивка": "…"},
 "пары": [{"n": 1, "onvif": "Imaging/Brightness", "родной": "Image/channels/1/Color/brightnessLevel",
           "шкала": {"вид": "линейная", "a": 0.392, "b": 0.0},
           "точки": [[128, 50], [204, 80], [51, 20]],
           "состояние": "найдена", "источник": "найдено автоматически, прогон QA-20261109-003"}]}
```

`шкала.вид`: «линейная» (`a`, `b`); «по диапазонам» (`a`, `b` считаются при сверке из объявленных диапазонов ONVIF и родного — для ручных пар вроде MaxGain ↔ GainLevel); «перечисление» (`{"значения": {"AUTO": "auto", "MANUAL": "manual"}}`); «по точкам» — шкала не линейная, кандидат, в сверке не участвует. `состояние`: «найдена» | «кандидат» | «подтверждена вручную». У ручных таблиц дополнительно `модели` (пусто — все модели бренда) и `прошивки` (пусто — все), а `источник` — «подтверждено вручную: кто, дата, на какой камере».

### Вход: Digest в `http.py` без нарушения AD-7

`request(method, url, *, content, headers, timeout, login: HttpLogin | None = None, max_bytes: int | None = None)`; новые исключения — `LoginRefused`, `LoginUnsupported`, `ResponseTooLarge`.

1. Табу (`check_http`, `check_onvif`, `MulticastGuard`, `check_web_request`) — до первой отправки и заново перед повтором с заголовком: проверяются метод, адрес и тело, а заголовок входа их не меняет; повтор — тот же запрос побайтно. Исключений в табу не добавляется: Digest — заголовок, а не запрос к адресу входа (`CAMERA_LOGIN_REQUESTS` не расширяется).
2. `HttpLogin(username, password)`: запрос входа камеры (`realm`, `nonce`, `qop`, `opaque`, `algorithm`) запоминается, дальше растёт `nc` — без лишнего 401 на каждый запрос. Первый запрос без заголовка получает 401 с запросом входа; попыткой входа он не считается.
3. 401 после отправленного заголовка: `stale=true` — новый `nonce` и один повтор (не отказ); иначе `login.refused = True` и `LoginRefused`. Дальше любой `request` с этим `login` — `LoginRefused` до отправки. Признак — общий для всего прогона `checks/rtsp_refusal.py` (`remember_refusal` / `refused_password(ctx)`): его уже ставят RTSP и веб-обход, теперь — и вход родного API, и `API-RUVER-1` (`LoginRejected`); стоит признак — `API-MAP-1` не входит вовсе, а отказ родного API видят «Картинка», «Кодеки» и стресс (одна попытка на камеру и прогон, S8; замечание plan-reviewer 09.11).
4. Только MD5 (`digest.py`), `qop=auth` или без него. Иной алгоритм, `auth-int`, параметры запроса входа длиннее 256 символов, с кавычками или управляющими символами — `LoginUnsupported`, пароль не уходит, «ошибка стенда: способ входа <…> не поддержан». Basic — только по HTTPS (как открытый пароль ONVIF в `CORE-CONNECT-1`); по HTTP — `LoginUnsupported` (см. «Решения» (директор 09.11)).
5. `max_bytes` — ответ читается потоком (`httpx.stream`); сверх предела соединение закрывается, `ResponseTooLarge`. Переадресации не выполняются (как сейчас).
6. Часы для Digest не нужны (`nonce` выдаёт камера), поэтому из «логики ONVIF» берётся только одна попытка и отказ как «ошибка стенда»; отказ ONVIF из-за часов в `CORE-CONNECT-1` снимает камеру раньше, сюда она не доходит.

`HttpLogin.__repr__` — без пароля; заголовок `Authorization` в доказательствах — через `redact`.

### Автопоиск S4

Только с `allow_writes`, только по ONVIF и только листы каталога со «S4 пишет»: `search.py` получает `ImagingWriter` (его `_guard`: защищённые блоки не уходят изменёнными) и `EncoderWriter` (белый список, `Multicast` как в снимке); иной ключ — `SearchRefused` до записи (тест).

Подготовка:
1. Настройки — каталог «S4 пишет», у которых ONVIF объявил годный диапазон (`declared()`, `options()`). Пары этой модели и прошивки, уже известные (библиотека или ручная таблица), заново не ищутся — их проверяет S3; так камера получает меньше записей. Переискать — удалить папку модели в библиотеке (F1 `api-map-library`).
2. Исходные снимки M0a и M0b наблюдаемых разделов с паузой `api.baseline_gap_s`; разошедшиеся параметры — «изменчивые». M0 = M0b. ONVIF state0 — полный XML настроек картинки и кодировщика профиля 1.
3. Порядок: картинка по каталогу, затем битрейт, кодек последним — смена кодека пересобирает параметры кодировщика, и её побочный эффект не должен остановить остальное.

На настройку `s` (диапазон `[lo, hi]`, текущее `v0`, доля `p0`):

4. `v1`, `v2` — две доли из {`api.share_low`, 0,5, `api.share_high`}, дальше всех от `p0` (не ближе 0,15) и друг от друга; целые — округлением. Битрейт: `v1` — середина, `v2` — `hi` (край: «объявлено, но не держит», живой случай Dahua .108); режим постоянного или переменного битрейта не меняется. Кодек: второй объявленный, затем назад (правила «Кодеков»: разрешение, частота и GOP не меняются; при текущих кодек недоступен — «пропущена»).
5. Журнал `intent` → запись `v1` → `sent`. Картинка — `ImagingWriter.write(key, v1, persist=False)`, кодировщик — `EncoderWriter.write(...)`. Fault или чтение назад другое → настройка «не найдена: камера не приняла значение по ONVIF (ответ OK, читается прежнее)» (Tiandy), возврат, следующая.
6. Пауза `api.apply_delay_s`, снимок M1 и ONVIF-снимок. `I` — листы ONVIF, которые мы меняли (из отправленного блока); `O` — прочие изменившиеся листы ONVIF, включая `protected_drift`; `Δ1` — параметры M1, отличные от M0. «Сдвинулся» — каноническое значение другое (числа — как числа, строки — без регистра и крайних пробелов); изменчивые, чувствительные и секреты не участвуют; появление или исчезновение параметра при смене кодека — не сдвиг.
7. `Δ1` пуст → та же запись с `ForcePersistence=true` один раз (камеры, которые показывают в родном API только сохранённую конфигурацию), снимок; снова пуст → «не найдена: родной параметр не сдвинулся», возврат, следующая.
8. **Побочный эффект → S5:** `O` не пуст; или `|Δ| > |I|`, где копии одного параметра в соседних экземплярах (одно имя, отличие только индексами, одно новое значение) — один параметр; или параметр `Δ` вне `expected(класс s)`. Так ловится .111: запись яркости (`|I| = 1`) сдвинула `brightnessLevel` и `GainLevel` (2), а в ONVIF — `Exposure/MaxGain` (`O`). Правило «больше, чем листов в записи» и копии — уточнение S5, см. «Решения» (директор 09.11).
9. Подтверждение: запись `v2`, снимок M2, `Δ2` — отличия M2 от M1; правило п. 8 действует и для `Δ2`. Пара для листа `s` найдена, если `Δ2` — ровно один параметр `c` (или одна группа копий), `c ∈ Δ1`, и:
   - число: точки `(v0, n0)`, `(v1, n1)`, `(v2, n2)` ложатся на прямую — `a ≠ 0`, `max|n − (a·v + b)| ≤ max(шаг родного, api.scale_residual_pct × диапазон родного)`; иначе «кандидат: значения не ложатся на шкалу ONVIF» с точками, в сверке не участвует;
   - перечисление (кодек, режимы): соответствие значений взаимно однозначно;
   - режим WB, WDR, BLC: параметр, сдвинувшийся в `Δ1` вместе с листом режима ONVIF и неподвижный в `Δ2`, — пара режима (n 5, 8, 10), перечисление по двум значениям;
   - битрейт: прочитанное назад `v2` меньше записанного больше `api.clamp_tol_pct` и в ONVIF, и в родном → точка в прямую не входит; «держит X при объявленном до hi» уходит в `API-RANGE-15`.
10. Возврат по ONVIF (журнал `restoring`): `ImagingWriter.restore(state0, touched)` / `EncoderWriter.restore(config0)`; снимок M3; сверка M3 с M0 по всем наблюдаемым разделам и ONVIF с state0 (с `protected_drift`). Совпало → журнал закрыт, следующая; нет → S5.
11. Бюджет: перед настройкой остаток `api.search_budget_s` не меньше её оценки (3 × (запись + `apply_delay_s` + снимок)); нет — остальные «не пробовали: не уложились в срок автопоиска»; возврат идёт в резерв 300 с.

Найденные пары — в таблицу прогона с источником «найдено автоматически, прогон <номер>»; трасса для п. 5 приложения и листа «Пары API» — `search.json`.

### Сверка S3 и S6

- Вход: M0 и state0 (значения до записи), объявленные диапазоны ONVIF, таблица пар. Старшинство: найдено в этом прогоне > `data/api_pairs` > `confirmed.json` библиотеки > найденное прошлыми прогонами (самое позднее). Найденная и ручная совпали — «найдено в прогоне …, подтверждено вручную»; расходятся — берётся ручная, в строке «прогон … нашёл иначе: …».
- По паре `n`: родного параметра нет в M0, он чувствительный или без значения → «пропущена: параметра … нет в карте камеры — пара из библиотеки не подходит»; тип не тот, что в паре → то же; изменчивый → «пропущена: значение меняется само (автоматика камеры)».
- Число («линейная», «по диапазонам»): `n_ожид = a·v_onvif + b`; `|n − n_ожид| ≤ max(шаг, api.compare_tol_pct × диапазон родного)` → «прошла», иначе «не прошла» с обоими значениями и путями: «ONVIF Imaging/Brightness = 128 (по шкале × 100/255 = 50), ISAPI Image/channels/1/Color/brightnessLevel = 70». «По диапазонам» без годных диапазонов с обеих сторон → «пропущена».
- Перечисление: сравнение без регистра по таблице; значения нет в таблице → «пропущена: значение X не встречалось при поиске и нет в ручной таблице». .111: «ONVIF Exposure/Mode = AUTO, ISAPI Image/channels/1/Exposure/ExposureType = manual» → «не прошла».
- `API-RANGE-<n>` (числовые пары): `[a·lo + b, a·hi + b]` против родного `[мин, макс]` ± `api.range_tol_pct` → «прошла» / «не прошла» (мелкая): «ONVIF 0…255 ≈ 0…100, ISAPI 0…50». Негодный диапазон с любой стороны (NaN, ±∞, `мин > макс`, |x| > 10⁹) → «не прошла: камера объявила негодный диапазон». Край из S4 → «не прошла» (серьёзная): «объявлено 512…5632 кбит/с и в ONVIF, и в CGI, а при H.264 камера держит не больше 1792».
- Пар нет (S6 без библиотеки и ручной таблицы, или S4 ничего не нашёл) → `API-MATCH-0` «пропущена: нет таблицы соответствий для модели — нужен прогон с галочкой «изменяющие»».

### Побочный эффект, журнал и возврат S5

- Журнал — новый вид `API` (`runs/pending-api/<адрес>_<порт>.json`), через `WritePass`: `page` — служба ONVIF, `kind` — ключ каталога, `old`/`new` — «Яркость 50» / «Яркость 80», `restore = {"xml": снимок ONVIF, "service", "token", "native": JSON-список [{"id", "запрос", "тело", "было", "осталось"}]}`. Перезаписывается на каждую настройку; `native` заполняется до первой родной записи.
- S5: автопоиск на камере останавливается, остальные настройки — «не пробовали: поиск остановлен на п. N». Возврат по ONVIF (п. 10), снимок M3. На каждый параметр M3 ≠ M0 при выполнении условий родной записи (раздел «Безопасность») `NativeRestorer` отправляет один `restore_request` со значением M0, перечитывает раздел и ONVIF (у пары вроде GainLevel ↔ MaxGain ONVIF возвращается следом). Затем финальная сверка всей наблюдаемой карты и ONVIF со снимками.
- Итоги: всё вернулось → `API-SEARCH-1` «не прошла» (мелкая; решение директора 09.11): «запись ONVIF «Яркость» сдвинула и другие параметры: ISAPI Image/channels/1/Gain/GainLevel 100 → 0, ONVIF Exposure/MaxGain 100 → 0; после возврата всё вернулось»; `API-RESTORE-1` «прошла». Не вернулось → `API-RESTORE-1` «не прошла», блокер, по каждому параметру «было / осталось», путь в родном API и как вернуть вручную: «по ONVIF: <настройка> = <было>» (есть пара и ONVIF принимает), «PUT /ISAPI/Image/channels/1/gain, GainLevel = 100» (есть шаблон возврата) или «веб-интерфейс камеры, раздел …»; журнал остаётся до следующего прогона.
- Журнал прошлого прогона (`settle_old`): ONVIF — как в «Картинке» (`restore_xml`, если читается наше `new`); `native` — только если сейчас читается ровно «осталось» из журнала; запрос сверяется с шаблоном возврата сборщика, тело — с текущей картой (тот же лист, значение в объявленном диапазоне). Иначе блокер `API-WRITE-LOST`, без записи.
- Камера пропала: `lost_abort`, `camera_back(api.reconnect_wait_s)`, затем возврат; не вернулась — журнал остаётся, `API-RESTORE-1` блокер; процесс снят — `API-WRITE-LOST` в `Runner._report_lost_write`.

### Библиотека S7

- Корень `<папка прогонов>/api-library/` (рядом с `pending-*`); папка `<бренд>/<модель>/<прошивка>/`, каждая часть — `safe_name(casefold(strip(x)), 40)` + «-» + 8 знаков sha256 исходной строки: разные модели не сливаются, `..` и имена Windows не проходят.
- Файлы `map-<прогон>-<место>.json` (карта, чувствительных значений в ней и так нет) и `pairs-<прогон>-<место>.json`; `confirmed.json` — пары, подтверждённые человеком на стенде (формат ручной таблицы; решение директора 09.11 — правкой файла). Пишет проверка в конце, после возврата: временный файл, `fsync`, `os.replace` (как `write_journal.save`); у каждой камеры свой файл — блокировки между процессами не нужны. Пары «кандидат» пишутся, в сверке не участвуют.
- Чтение (S6): `pairs-*` папки по имени по убыванию (номера прогонов упорядочены), не больше 50, и `confirmed.json`; каждый ≤ 2 МБ, `resolve()` внутри корня, ссылки пропускаются; `jsonschema` по формату версии 1; `n` — из каталога, строки ≤ 256 символов, числа конечные; файл не прочитался — пропускается с пометкой в сводке приложения. На каждый `n` — по старшинству из «Сверки».
- Данные библиотеки не управляют запросами и записью: из них берутся только `n`, родной `id` (ищется в карте этого прогона) и шкала.

### Пороги (`thresholds.yaml`, `api.*`)

| Ключ | Старт | Зачем |
|---|---|---|
| `apply_delay_s` / `baseline_gap_s` | 2 / 2 с | пауза после записи до снимка: камеры применяют не сразу / между исходными снимками для поиска изменчивых |
| `share_low` / `share_high` | 0,2 / 0,8 | доли диапазона для `v1`, `v2` |
| `scale_residual_pct` | 2 % | отклонение точки от прямой, от диапазона родного (не меньше шага) |
| `compare_tol_pct` / `range_tol_pct` | 1 / 1 % | допуск сверки значения / диапазона |
| `clamp_tol_pct` | 2 % | «не держит»: прочитано меньше записанного |
| `request_timeout_s` | 5 с | запрос к родному API |
| `map_budget_s` / `search_budget_s` | 120 / 900 с | снятие карты / автопоиск на камеру |
| `reconnect_wait_s` | 120 с | ожидание пропавшей камеры перед возвратом |

Источник стартовых — «стартовое значение: уточнить на живых камерах». Значение ≤ 0 или `share_low ≥ share_high` → «ошибка стенда: проверьте thresholds.yaml». Пределы защиты от враждебного ввода (размеры, число запросов) — константы кода, не пороги: это не допуски проверки.

### Табу и выходы к камере

- Новых выходов к камере нет: сборщики и `NativeRestorer` ходят только через `http.request`, «Рувер» — через `RuverClient` (тоже `http.request`), ONVIF — через `SoapClient`; `tests/test_architecture.py` — без новых исключений. Карта из трафика новых запросов не делает: браузер только записывает то, что страница уже отправила, и под своими проверками (`check_web_request`, `check_web_danger`).
- Чтение: только GET по шаблонам сборщика (статический список в коде, ревью в PR); путь и параметры дополнительно проходят `web_danger_word` и `is_write_request` — изменяющий или опасный GET (`magicBox.cgi?action=reboot`) не уходит; адрес — только `address:port` камеры со стенда; переадресация не выполняется. Адреса из ответов (`Hyperlinks`, `declarationURL`), из трафика и из библиотеки не открываются никогда.
- Запись при автопоиске — только ONVIF и только листы каталога со «S4 пишет» (`SearchRefused` до отправки), через `ImagingWriter` (защищённые блоки `Exposure`, `IrCutFilter`, `Focus`, `ImageStabilization` не уходят изменёнными) и `EncoderWriter` (белый список, `Multicast` как в снимке, `MulticastGuard` в `http.py`). Разрешение, частота, GOP, сеть и учётные записи не меняются.
- Чтение разделов сети, пользователей и безопасности разрешено AD-7 («только чтение»), но значения отбрасываются при разборе: в карте, снимках, `exchanges.txt`, журнале и библиотеке их нет.

### Запись родным API (только возврат S5)

`NativeRestorer` отправляет запрос, только если выполнены все условия; иначе — блокер с путём для ручного возврата:

1. Галочка «изменяющие»; идёт S5 этого прогона или закрытие журнала `API` прошлого прогона.
2. Параметр после возврата по ONVIF отличается от снимка M0 этого прогона, не изменчивый, не чувствительный и не секрет.
3. Класс раздела — «картинка», и у сборщика есть шаблон возврата: Hikvision — `PUT /ISAPI/Image/channels/<цифры>/<подресурс из списка>`; Dahua — `configManager.cgi?action=setConfig` с одним ключом из имён картинки; «Рувер» — операция записи раздела картинки из `ruver_api_map.json` (`RuverClient` сам отказывает вне карты). Кодировщик, наложения, события и всё прочее — только вручную. У Tiandy, Beward и карт из трафика возврата родным API нет.
4. Значение — только из M0 этого прогона; у журнала прошлого прогона — только если сейчас читается ровно «осталось» из журнала, а запрос и тело заново сверены с шаблоном и текущей картой. Из библиотеки, трафика, ручных таблиц и ответов вне M0 значения и адреса не берутся.
5. Тело: Hikvision — поддерево M0 этого подресурса (≤ 16 КБ), перед отправкой разбирается `defusedxml` и сверяется: отличается от текущего только сдвинувшимися листами; Dahua — `ключ=значение`, ключ `^[A-Za-z0-9_.\[\]]{1,128}$`, значение ≤ 256 символов, URL-кодирование.
6. Журнал `API` со списком `native` записан (`fsync`) до отправки; одна попытка на параметр, без повтора по `TransportError` — перечитать раздел и ONVIF и решить.
7. Табу `http.py` действует как всегда (`check_http`, `check_web_request` по словам-признакам); галочка его не снимает.

### Вход и секреты

- Новых секретов нет: пароль — из `keyring` (`get_password`), логин — с места стенда. Digest передаёт хеш, не пароль; Basic по HTTP не отправляется вовсе (открытый пароль). Заголовки `Authorization`, cookie и `X-Session-ID` в доказательствах вырезает `redact`; `HttpLogin.__repr__` и тексты исключений без пароля и заголовков.
- Одна попытка входа на камеру и прогон (S8): `LoginRefused` липкий, признак отказа общий с `API-RUVER-1` и веб-обходом через `ctx.extra`; Hikvision блокирует вход после нескольких отказов (`maxIllegalLoginTimes` в `Security/capabilities` .114) — лишняя попытка стоит камеры на стенде.
- Запрос входа от камеры — недоверенный ввод: параметры ≤ 256 символов, без кавычек, CR, LF и управляющих символов, алгоритм только MD5 — иначе пароль не уходит.
- Секреты в ответах (пароли, ключи, соли, токены): значение отбрасывается при разборе; `api-map.json`, `api-pairs.json` и `exchanges.txt` перед записью проходят `redact`, тела ответов с чувствительными параметрами в `exchanges.txt` не попадают.

### Враждебный ввод

| Ввод | Риск | Мера |
|---|---|---|
| огромный или бесконечный ответ | память, зависание процесса камеры | `http.request(max_bytes=2 МБ)` потоком, тайм-аут 5 с; ≤ 80 запросов и ≤ `api.map_budget_s` на карту; ≤ 5000 параметров (сверх — «обрезано» с причиной); `api-map.json` ≤ 8 МБ |
| XML с DTD и сущностями (billion laughs, XXE), глубокая вложенность | память, чтение файлов стенда | `defusedxml` (DTD и сущности запрещены; `DefusedXmlException` → раздел «ответ отвергнут»); обход дерева без рекурсии, глубина ≤ 32 |
| JSON-бомбы: вложенность, числа в тысячи цифр, `1e999` | `RecursionError`, `ValueError` (предел цифр int), бесконечности | размер проверен до разбора; `RecursionError`, `ValueError` → раздел «ответ не разобран»; обход без рекурсии; число — конечный float, \|x\| ≤ 10⁹, иначе строка |
| «ключ=значение» (Dahua, Beward): миллионы строк, ключи с мусором | память, мусорные id | ≤ 2 МБ, ≤ 5000 ключей; ключ `^[\w.\[\]-]{1,128}$`, иначе строка пропускается со счётом в «ошибках» |
| мусорные диапазоны: `min > max`, NaN, ±∞, `opt` из 10⁵ значений, `max` без `min` | ложные пары, запись мусора | `{"негодный": причина}` и строка `API-RANGE` «не прошла»; `opt` ≤ 256 значений; значения для записи S4 берутся только из диапазона ONVIF (`declared`, `options`), родной диапазон в запись не идёт никогда |
| имена, пути, значения параметров с разметкой, `=`-формулами, управляющими и невидимыми символами (Cc, Cf, RTL) | XSS в HTML-протоколе, формулы в Excel, подмена текста | Jinja2 с автоэкранированием, `QTextDocument` — только локальные ресурсы из `base_dir`; Excel `data_type = "s"`; символы Cc и Cf заменяются видимой меткой; имя ≤ 128, значение ≤ 1024 символов с пометкой «обрезано» |
| запрос входа камеры (`realm`, `nonce`, `opaque`, `algorithm`) | внедрение заголовка, понижение до Basic, неизвестный алгоритм | проверка из «Вход и секреты»; иначе `LoginUnsupported`, пароль не уходит |
| переадресация 3xx, ссылки в ответах | уход запросов на чужой адрес (SSRF), утечка Digest | `http.py` не следует переадресациям; ссылки не открываются; трафик чужих хостов отбрасывается |
| трафик веб-обхода (токены в адресах и телах) | секреты в карте | только имена параметров; значения — только из ответов GET и по правилам чувствительности; `redact` |
| паспорт (производитель, модель, прошивка) как имена папок библиотеки | обход пути, имена Windows, слияние разных моделей | `safe_name` + 8 знаков sha256; `resolve()` внутри корня библиотеки; ссылки не читаются |
| библиотека и `confirmed.json` (прошлые прогоны, правка человеком) | подмена → ложные «не прошла», чтение вне папки | ≤ 2 МБ, `jsonschema`, знакомая версия, `n` из каталога, родной `id` обязан быть в карте этого прогона; не прочитался — пропуск с пометкой; данные библиотеки не управляют запросами и записью |
| журнал `API` прошлого прогона | отправка подложенного тела или адреса | `native` сверяется с шаблоном возврата сборщика и текущей картой (п. 4–5 «Записи родным API»); не сошлось — блокер без записи |

### Файлы

`api-map.json`, `api-pairs.json`, `search.json`, `exchanges.txt`, `pair.txt`, `restore.txt` — в папке доказательств строки через `safe_name`; журнал — `runs/pending-api/<адрес>_<порт>.json` (имя из адреса стенда, `journal_file`); библиотека — `runs/api-library/…` с очищенными именами. Ни одно имя не строится из ответа камеры. Образцы ответов в `tests/data/` — с заменёнными серийным номером, MAC, именем устройства и адресами; документы вендоров — только ссылками (never.md).

### OWASP Top 10

- A01 (доступ): только адреса стенда, без переадресаций и без адресов из ответов; родная запись — только возврат по условиям выше.
- A02 (криптография): Basic по HTTP не отправляется; Digest MD5 — выбор камеры, сильнее она не предлагает; пароль только в `keyring`.
- A03 (внедрение): XML и HTML — экранирование, Excel — текст, заголовок входа — проверка параметров, ключи CGI — белый список символов.
- A04 (небезопасный дизайн): автопоиск пишет только ONVIF; данные библиотеки и трафика не становятся запросами.
- A08 (целостность данных): журнал и библиотека — атомарная запись; при чтении — схема, версия и пределы.
- A09 (журналы): обмены через `redact`, без тел чувствительных разделов.
- A10 (SSRF): ссылки из ответов, трафика и библиотеки не открываются.

MITRE ATLAS не применим: ML- и LLM-компонентов нет, подбор шкалы — линейная прямая по трём точкам.
