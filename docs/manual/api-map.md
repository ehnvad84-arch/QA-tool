# API камеры: карта и сверка с ONVIF

Проверка «API камеры: карта и сверка с ONVIF» читает собственный (родной) API камеры и сверяет его с ONVIF. Она идёт у всех камер в сетевой фазе, после обхода веб-интерфейса и проверки API «Рувер».

Программа узнаёт производителя по паспорту ONVIF камеры, а если паспорт пуст или незнаком — по полю «Производитель» на экране «Камеры». Родной API читают Hikvision (ISAPI), Dahua (CGI) и «Рувер» (API по карте программы). Для Tiandy и Beward адреса родного API пока не подтверждены: строка «пропущена» с причиной.

Программа только читает: каждый запрос — чтение, запросы перезагрузки, сброса, обновления, выгрузки настроек и записи не уходят никогда. Вход — тем же логином и паролем, что ONVIF, одна попытка на камеру за прогон: если камера отвергла пароль раньше (видео, веб-интерфейс, API «Рувер»), родной API не пробуется, строка «ошибка стенда».

Что в протоколе:

- **«API камеры: карта и сверка с ONVIF»** — «прошла: карта снята» с числом разделов и параметров. Значения сети, учётных записей и безопасности в карту не попадают — только их описание. Полная карта — в доказательствах строки, файл `api-map.json`.
- **Сверка с ONVIF** — строка на каждую настройку, которая есть и в родном API, и в ONVIF: значение («не прошла» — задача программистам: одна настройка читается по-разному) и объявленный диапазон. Откуда взято соответствие — подтверждено вручную или найдено программой — указано в строке.
- Если соответствий для модели нет, одна строка «пропущена: нет таблицы соответствий для модели — нужен прогон с галочкой «изменяющие»».
