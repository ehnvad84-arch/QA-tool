## Именование

- Файлы и модули: snake_case.
- Классы — PascalCase, функции и переменные — snake_case.
- Идентификатор проверки: `<МОДУЛЬ>-<ГРУППА>-<N>`, например `API-IMAGE-3`, `WEB-VIDEO-12`. Проверки из onvif-tt сохраняют их ID (`MEDIA2-1-1-4`), наши ONVIF-дополнения — с префиксом `RUV-`.
- Ветки и коммиты — по .workflow/WORKFLOW.md, раздел «Git».

## Куда класть новые файлы

- Новая проверка → `src/qa_tool/checks/<модуль>/`; у каждой проверки — описание «что делаем, что ожидаем», оно же уходит в протокол и каталог проверок.
- Новое оборудование стенда → `src/qa_tool/drivers/stand/`; у каждого драйвера — самопроверка и mock для тестов.
- Тесты → зеркально в `tests/`.
- Руководства и справка F1 → `docs/manual/`; схемы и перечень стенда → `docs/stand/`.
- Документация фичи → docs/work/<slug>/

## Стиль кода

- Источник правды — `pyproject.toml` (ruff). Команда — в AGENTS.md, раздел HOW.
- Здесь только то, что линтер не проверяет:
  - Тексты интерфейса, протоколов и сообщений — по-русски, без жаргона: протокол читает ОТК.
  - У каждого элемента интерфейса — подсказка (tooltip) и ссылка на раздел справки F1; без них сборка не проходит.
  - Результат проверки — только «прошла / не прошла / пропущена / ошибка стенда» с причиной и доказательством; «ошибка стенда» не превращается в задачу программистам.
  - Пороги и допуски проверок (время перехода, % потерь, изменение яркости) — в конфигурации, не в коде.
